# AutoDL / RLinf 工作区规则

- 每个新任务开始时，先完整读取本目录的 `PROJECT_CONTEXT.md` 和 `HANDOFF.md`，再读取 `HANDOFF.md` 指向的当前专题单一事实源；历史快照只在追溯时按需读取。
- 专题实现规则、参数与调用链放在对应专题文档，不写回根目录高层文档。专题入口统一由 `HANDOFF.md` 路由。
- 动态实验状态的可信顺序：服务器现场只读检查 > 当前交接文件 > 历史文档、旧聊天或 Memories。训练 step、GPU/RAM、进程、日志、checkpoint、Git HEAD 和 dirty tree 必须刷新后才能称为“当前”。
- `HANDOFF.md` 记录当前任务已经取得的授权边界；超出该边界时默认只读。停止进程、删除或覆盖文件、安装依赖、下载模型以及其他破坏性操作必须另有明确授权。
- AutoDL 密码登录使用 Paramiko，把密码仅注入当前进程，设置 `look_for_keys=False`、`allow_agent=False`，先做只读身份探针。OpenSSH `BatchMode=yes` 无法回答密码提示，不代表密码认证不可用。
- Windows 本机用于阅读、编辑和保存文档、代码与 diff；项目 compose、import/compile、测试、smoke 和训练默认放到服务器。实际授权范围以当前 `HANDOFF.md` 为准。
- 从第一次实现操作起维护细粒度实施账本，逐条记录命令、目标文件、修改、结果、问题、原因、修复与复测；不得只在结束时补写笼统摘要。
- 保留用户现有 dirty tree 与未跟踪文件；修改前先核对精确目标和基线。大文件、checkpoint 和运行产物留在服务器，不复制进文档仓。
- 文档分层保持单一事实源：根目录仅放稳定规则与当前路由；专题目录放唯一实施计划和证据；历史材料移入 `docs/project-history/` 或专题 history，并由索引维护，不复制成并行计划。
- 实施优先完成一个连贯主体批次，再做少量高信息量检查。失败后保留最小证据、定位一个原因、实施一个窄修复并复测，不预设多套复杂兜底。
- 在真正的 smoke 或正式训练前，向用户展示完整 resolved config、精确命令、输出目录、预计资源和停止条件，并按当前授权边界取得批准。
- 任务结束时更新 `HANDOFF.md` 的当前状态、待办、风险和下一步；只有长期规则变化时才更新 `PROJECT_CONTEXT.md`。
