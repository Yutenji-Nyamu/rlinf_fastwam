## 3. 每次只留最后一个checkpoint，是否可以？

如果只需要最终恢复/部署，且不再需要中间模型，**可以淘汰较早代的大文件**。但“最后一代”必须是最后一个完整有效恢复点，不是数字最大或目录刚创建的一代。活跃run当前正在写的新一代不能计入保留点替换。

更稳妥的保留规则：

1. 每条有效实验至少保留最后完整一代，所有必需rank分片、metadata、算法状态一起保留。
2. 需要比较最好结果时，另保留最佳固定评估对应的已保存模型；最后一步未必最好。Sidney已核对的最佳保存点70（fixed26/32），当前恢复起点100也建议暂留；19:36最新完整保存为110。
3. 旧smoke/probe不需都保留多代；先保存代码、配置、验证结果和小状态，再讨论删除多余大权重。

| 文件 | 作用 | 删除边界 |
|---|---|---|
| `model_state_dict/full_weights.pt` | 汇总模型参数，用于部署、单独评估或重新初始化 | 只有此文件不等于可以恢复Adam/训练状态；旧代删除后不能直接复评该模型 |
| `local_shard_checkpoint/checkpoint_rank_*.pt` | 按rank保存模型、优化器、scheduler等训练状态 | 保留代不能只留下某一个rank；旧代删除任意必要分片后即失去完整恢复能力 |
| `dcp_checkpoint/*.distcp`＋`.metadata` | DCP分片与索引 | 分片不是相互替代备份；保留代要完整，metadata单独不能恢复 |
| BC的replay/learner/DVAC sidecar、配置、日志、TB/CSV | 数据池、计数/权重标定和实验记录 | 本次候选不删这些小文件；replay有时并不小，不能泛称全部sidecar只有几KB |

依据：部署`rlinf/hybrid_engines/fsdp/strategy/base.py`184—342行，原始片段[SZ_CHECKPOINT_ROLES_AND_PROBES_20260905.txt](SZ_CHECKPOINT_ROLES_AND_PROBES_20260905.txt)；BC本轮两代实体和状态读回验收。不同历史算法/版本实际恢复文件仍须逐项核对，不能把当前BC结构套到所有旧run。

删除旧大文件不会抹掉已有日志/曲线，但会永久失去相应历史步的恢复或重新评估能力；若没有外部备份，不能承诺可恢复。

## 4. 建议怎样精确清，能释放多少？

### 5.3 除了这批，还建议什么？

按优先级，而非一次全删：

1. **两个BC组件探针的4个大文件：约33.40GiB。** 一个验证旧同步，一个验证SFT/FSDP保存恢复；已有通过的完整smoke和轻量验证记录，可讨论淘汰探针权重。它们不属于正式训练成果，也没有混入上述81文件或856.35GiB。
2. **已通过的BC v7、DVAC smoke各第1代：4文件约34.38GiB。** 每个run完整保留第2代、全部代码/配置/结果/小状态，便于留一份验收样本。这会失去首轮模型再加载能力，但已核验的记录与曲线不变。
3. **旧π0.5和Fast-WAM非最后代：初筛约169.10GiB。** 142.18＋26.92，须先理清各run续训来源/最佳模型；不是正在训练的Sidney π0.5。不作为第一批无条件删除项。
4. DSRL早期点约90.35GiB可另讨论，暂不动；RLT、现用模型/环境/仿真资产、共享Ray和他人数据不建议这次清理。本人/home不紧张，优先级远低于/data旧权重。

**旧GRPO/PPO＋两个组件探针＋v7/DVAC早期smoke三项合计约415.51GiB**，不包含正在训练的Sidney、DSRL/RLT，也不包含刚结束的GPU6 v8。GPU6 v8于20:05:53完成两代保存，其第1代两大文件另约17.19GiB，可以以后按同样规则讨论，但未擅自追加到19:36候选清单。

以上是可供用户批准的清理建议，不是已执行删除、承诺实际腾空空间或新的删除授权。保留点验证、最佳点选择、跨run路径依赖和文件硬链接/打开状态仍需在执行前完成；没有备份的旧模型删除后不能恢复。
