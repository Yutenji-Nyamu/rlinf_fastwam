**故障分两段。** 凌晨的显存与渲染分配失败解释了上游实验和两个候补为什么退出。上午的驱动锁同时挡住新任务初始化和旧任务的设备释放，解释了为什么接下来的换卡失效。7 卡这两种现象相隔约九小时，日志未建立直接因果关系。

**不重启整机的恢复路径。** NVIDIA 对 Xid 109 推荐清空报错卡上的计算、图形和监控客户端后做单卡复位。该机为 H100 NVSwitch。排空后，管理员可以按现场状态分别指定物理 4 卡 `0000:87:00.0` 和物理 7 卡 `0000:c7:00.0`，单独复位仍有故障的设备。复位前须再次核对 GPU 使用者、进程和驱动响应。本次检查时旧进程本身卡在释放设备，其他用户的 0–3 卡任务也打开了相关设备。此时跨卡卸载驱动或整机复位会影响共享任务。

**接回次序。** 4/7 卡先续 RT2 FastWAM GRPO 拨开关；5/6 卡先续 Dojo π0.5 GRPO 丢瓶子。两项上限 300 轮。之后七个正式 clean RLT 候补依次接班，四个卡位各有一个无保存兜底。进程启动与完成新参数更新分别记录。进程崩溃时可以换候补；驱动卡死时，同一卡上的候补也依赖它，连续重试会积累阻塞进程。
