# Dojo 丢瓶子 · 每瓶 0.25 的 GRPO

任务为 `put_bottles_into_dustbin`。原始 Dojo π0.5 从第 0 轮开始，两卡每卡 32 个环境，每轮 128 局，8 局一组，50 步动作块，每局最多 700 步。每轮更新两次，学习率 5e-6，clip 0.2，预算 200 轮。

训练端读官方 RewardManager 已计算的投瓶阶段。夹爪松开，达到新的入桶数量时，首次跨过的每一档给 0.25。一局最多 1 分。阶段记录本局达到过的最大进展，已经获得的分数不会因再次抓放而重复发放。官方完整成功直接补齐到四档。模型训练使用每条轨迹的总分做组内比较，保留总分有差异的八局组。最高达到四瓶、双臂尚未归位，也可得到训练分 1。独立评估继续统计官方完整成功，即四瓶在桶内并完成归位。逐局材料分别保存瓶数、达到各档的动作步、实际回报和完整成功标志。

本次把训练探索噪声从 0.3 改到 0.5，同时加入投瓶进度奖励。比较对象是此前二元奖励、噪声 0.3 的丢瓶子运行。新实验可以评价组合效果，单项贡献需固定另一项后比较。训练沿用动作块边界渲染，独评沿用逐步渲染。第 0 轮使用原始权重实测同一面板 32 局，旧原模型 76/128 作为重复评估参考。第 2 轮与之后每 10 轮做 32 局独评，原有完整成功指标用于选择模型。

CPU 测试经过仿真接口的实际动作块函数、RLinf 生产 actor 的数据筛选、轨迹得分和 GRPO 优势。覆盖同一档重复、跨动作块、终止后填充、四瓶未归位、完整成功、同分组和稀疏的四分之一奖励。运行 `python tools/dojo_grpo/test_bottle_progress.py`。本目录的运行配置使用环境变量指向模型、部署与结果目录。逐局字段见训练和评估的 `native-g*/completed-waves.jsonl`。

初始训练奖励来自本次实验设计。投瓶判定直接复用 [RoboDojo 任务实现](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/main/task/RoboDojo/tasks/put_bottles_into_dustbin.py)。阶段奖励的对照依据见 [Temporal GRPO 表 1](https://arxiv.org/html/2608.13026)。Flow-SDE 探索依据见 [πRL](https://arxiv.org/abs/2510.25889)。0.5 也用于此前跑通的 RT2 π0.5 GRPO。
