# RoboTwin FastWAM GRPO on turn_switch

This run uses the released RT2 three-camera, 14-dimensional FastWAM and its matching normalization. The official task cap is 400 actions. The RLinf experiment evaluates and trains on 192 actions, with eight replans of 24 executed actions from a predicted horizon of 32. The original checkpoint uses ten denoising steps and scheduler shift 5. Evaluation uses the original inference sampler, with 32 fixed evaluation layouts. The training and evaluation seed pools are the disjoint 1,000/32 pools used in the earlier same-task FastWAM study.

The resolved configuration derives from commit `62526cc95047c8a4a6e948a76be8eeec8a3926de` and its two-GPU 256-trajectory training run. Two GPUs each simulate 16 environments. Eight waves yield 256 trajectories per round, in groups of eight. Train only the action expert. Adam uses a learning rate of 5e-6. GRPO uses a policy-ratio clip of 0.2, two optimization epochs, a global batch of 1,024 chunk positions and a per-rank microbatch of 2. Flow-SDE exploration is 0.3. The trainable master weights and Adam moments are FP32, with BF16 model forward. Install the update audit in the Python path for the actor patch. The first real optimizer step samples local parameters before and after the update. The GPU memory observer records total device occupancy every ten seconds.

A fresh formal run targets 100 rounds, with a baseline before training and an independent evaluation every five rounds. A rolling full checkpoint is written after round 1 and every five rounds. The best evaluated trained checkpoint is archived separately. Historical public Clean scores for turn_switch are 61% in the original FastWAM paper and 39% in the RoboTwin leaderboard.

The separate Dojo pouring diagnostic compares a fresh process with a second native reset inside the same process on the same 32 layouts. It runs after the first complete training checkpoint, on one of the two Dojo GPUs, in a separate simulator. The same official simulator, cameras, physics and success checks are used. The first reset is followed by a single hold action before the second reset. Raw reset times, requested and actual layouts, instructions and differences in initial observations are retained. This measures reset cost and agreement at episode start. The probe has a 15-minute limit and its trajectories are excluded from training.

The original model succeeded on 13/32 evaluation episodes (40.625%). That evaluation used the same model, sampler, seeds, and 192-step task. With 16 environments per device simultaneous actor residency left under 1 GiB at the sampled peak. The production config offloads idle actor parameters and optimizer state during rollout using the existing RLinf option.

Measured Dojo time in the first 64 training episodes (32 per device, concurrent): 19.1–19.2 min executing actions, 9.9–10.0 min obtaining observations, and 5.0 min resetting per device. Process creation to the start of native reset took about 50 s. Reset reuse is being tested independently. See the [Isaac Lab reset implementation](https://github.com/isaac-sim/IsaacLab/blob/main/source/isaaclab/isaaclab/envs/direct_rl_env.py).
