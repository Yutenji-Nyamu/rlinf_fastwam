# 原始π0.5：执行长度与N1/N10差距扫描方案

状态：2026-10-24讨论稿，没有启动。目标是找到多步生成确实帮助闭环执行的可复现设置，同时保留完整扫描结果。

## 第一阶段

|项目|方案与依据|
|---|---|
|权重|同一个现用原始Sidney π0.5，N1/N10共用|
|预测长度H|固定50，保持训练分布|
|执行长度C|10、20、30、40；现有50作为参照。优先C10/C20，有近邻文献与本项目经验|
|生成步数N|每个C分别1和10；同C内配对比较|
|任务/回合|50任务×每任务8回合，8个新条件=计划3200回合；错误单列，主要差值按共同有效任务计算|
|动作总预算|各任务官方上限，保持400–1700的既有任务配置；不足整块时只执行剩余前缀|
|并行|复用验收的每卡3任务×8环境，两卡最多48环境；每任务一批，模型常驻，无录像、逐动作日志和信号采集|
|种子|同任务同slot同初始环境种子；同C内N1/N10共享初始噪声规则。不同C会改变观察与查询时间，不声称逐物理动作噪声完全一致|
|存档|配置、每回合seed/成功/动作数/查询数/耗时、每任务缺测原因、汇总、轻量日志与绘图表|
|故障|继承已有单任务超时/异常清理与继续调度；正常执行失败照常计失败|

C10表示看一次画面后只执行预测前10个动作，再看新画面重算剩余动作。它可能救回N1，缩小差距；也可能让较准确的N10更有效地纠错，扩大差距。方向必须实测。

当前仿真控制器还会对执行前缀做原生轨迹处理，因此C改变既影响重新观察频率，也影响每次提交给控制器的路径长度；不更换规划器/平滑器、不增加动作插值改法。

## 时间与选择规则

现有C50两卡全任务一次约32–33分钟；8个条件按此折算约4.3小时。C10的模型查询最多约5倍，并不代表总用时5倍，因为动作/初始化仍占主要时间；同时成功早停和仿真轨迹也会变化。先按4–8小时粗预算，第一对C完成后再校准，不承诺精确ETA。

所有C都画N1/N10平均分、差值、逐任务差、缺测和总耗时，不只展示最大差距。若某C差距稳定且N10本身成功率合适，再用独立新种子扩到每任务32或64回合确认；重要单任务可到128。选设置用第一批，报告验证用第二批。

若仍无明显整体差距，就保留这个结论；蒸馏的价值应看能否保持或改善质量并节省模型推理，而不是保证原始N1一定差。

## 其他因素优先级

1. 先做C，固定其余项。它是自然的部署参数，最容易解释。
2. 再按任务结构/示范长度分组看差异：精细接触、交接、长链条可能更敏感，但不能只挑有利任务后宣称覆盖50任务。
3. 若需要更强老师，先验证更高质量的多任务权重在相同协议下N10确实更强，再在该同一权重内比较N1/N10。不能把两个不同权重的差当纯步数差。
4. 官方随机化场景可作为独立泛化套件；不与Clean主结果混算。
5. 噪声幅度、求解器时间网格、动作平滑/集成、观测预处理都会影响成功率，但本轮不一起扫。原方法/模型差异需先找实现依据。
6. 统一400动作目前没有好证据：现有轨迹的事后差距仍小，还剪掉长任务成功机会。保持原生上限，另画成功率随截止动作数的曲线即可。
