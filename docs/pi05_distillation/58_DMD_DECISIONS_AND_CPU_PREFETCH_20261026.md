# DMD修整收敛与CPU供数验证

2026-10-26。本轮用户允许试做CPU供数优化，继续讨论DMD；正式4–7训练及仿真器未修改。

## 先分清三个计数

- 一次训练更新：抽一个全局384窗口的batch，完成参数更新。直接蒸馏全计划55,650次。
- 一轮正式评估：遍历50个任务，当前每任务8回合；全程十来轮，不是55,650轮。
- 一次评估后的重载：评估完成，再创建训练进程并恢复模型、优化器和数据。约4.2分钟/轮；十几轮合计约一小时。
- 每次训练更新省1秒，55,650次累计15.46小时；此估算来自更新次数，与重载无关，也不是当前剩余时间收益承诺。

## 学习率依据及方法区别

|设置|出处|解释|
|---|---|---|
|直接蒸馏学生峰值2.5e-5|已验收π0.5动作专家实配；OpenPI CosineDecaySchedule峰值同为2.5e-5|本地warmup167，按当前总预算衰减；并非照搬官方全部时间表|
|OneDP学生1e-6固定、辅助2e-5固定|ICML 2025最终论文附录超参数表；已核原文摘录与本地实配|是有来源的起点，尚未证明是π0.5 flow适配最优值|
|目前每次更新F1/G1，计划F5/G1|当前train.py；用户已接受5:1，DMD2提供机制与对照依据|五次独立辅助optimizer更新，不是五次梯度累积后只更新一次；学生更新一次计一个step|

[OneDP正式论文](https://proceedings.mlr.press/v267/wang25ba.html)、[OpenPI学习率和优化器](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/training/optimizer.py)、[DMD2](https://arxiv.org/html/2405.14867v1)。本地原文摘录位于本线程onedp_cp_research1021/onedp_paper.txt第644–667行。

两种方法共享同一观察、指令、状态、模型接口与动作专家训练范围；都不调用仿真器训练，也都没有专家动作FM监督。直接蒸馏：同一噪声→老师10次计算得到固定目标，学生1次得到动作，真实14维端点MSE。OneDP：学生1次生成动作→给动作加噪→辅助学习当前学生的噪声预测；学生更新时老师/辅助在同一加噪动作上给出不同预测，用差异组成修正方向。它没有给每份噪声算一个老师10步答案，其学生loss是表达该方向的代理量，不宜与端点MSE大小比较。辅助loss本身是噪声预测MSE。

25倍学习率差不等于25倍实际参数移动：损失方向、归约、时间权重和优化器状态不同。学习率值得后续小范围比较，但先不要与5:1、物理维筛选一起大幅修改。若改用已学好的直接蒸馏学生初始化DMD，是endpoint初始化+DMD微调的组合实验，应与从原始基座的OneDP区分。

## 本轮确定与暂缓

- 用户已接受：辅助5次/学生1次；学生损失只算真实14维，H50保持。方法代码本轮尚未实施。
- 辅助先保留完整32维分布拟合，分开记录真实/填充维误差。不要将填充维数量当成已测梯度占比。
- 学习率先保持1e-6/2e-5；修复后若学生实际移动仍小，再考虑少量更大学习率对照，不直接跳到2.5e-5。
- 暂不添加新奖励、GAN、投影、初始化混合或改变H50/batch。DMD学生loss不会为了看起来像直接蒸馏而换成同一个MSE。

## CPU供数：实现及实测

独立分支`codex/distill-cpu-prefetch-20261026`，服务器隔离目录`/data/chenyiteng/deployment-20261026/cpu-prefetch-discussion`。复用已跑通data.py，增加同进程解码线程和有序1–2批预取；训练入口新增`--decode-workers`、`--prefetch-batches`，默认0/0，方法实配和checkpoint配置字段不变，运行回执另记供数开关。旧完整checkpoint仍遵守原配置核对。

CPU代表样本为adjust_bottle/open_microwave/scan_object各一条真实轨迹，每批192窗口、576张图片；交错测试串行/4线程/8线程各三次，避免全把机器瞬时变化算成收益。

|解码线程|准备一批的中位耗时|
|---|---|
|原串行|2.590秒|
|4|0.851秒|
|8|0.556秒|

选择候选8线程＋预取1批。该供数环节约快4.65倍；没有测完整GPU训练每步时间，不能外推整步同样加速或承诺节省多少小时。多个训练rank同时启用后的竞争也尚未实测。只读共享压缩图片，不为每个线程复制整套数据，当前批之外只小队列留下一批。

5项CPU检查通过：串行/并行/预取输出逐元素一致；原双卡与梯度累积抽样及断点恢复顺序一致；Python/NumPy/Torch全局RNG不受预取影响；提前关闭及解码异常能退出并上报。真实样本另核了图像、动作、状态、指令一致。CUDA未初始化。

本轮只运行CPU准备测试，未启用GPU、仿真或改正式队列。下次修整DMD实现时，可在简短GPU训练对照中核端到端耗时，再把已验证供数开关用于两种方法。轻量证据：`docs/experiments/cpu-prefetch-20261026/`。
