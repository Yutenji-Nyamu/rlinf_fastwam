# OneDP与直接蒸馏：哪些应对齐

2026-10-26。本轮对照实际部署配置、loss/model/data/train、完整评估结果；只讨论，未修改4–7卡正式训练。

## 结论

两者的大部分非方法设置已一致。最明确的差异是**学生损失包含哪些动作坐标**：直接蒸馏为H50×14，OneDP为H50×32。两者都预测50动作、评估只执行前10；因此“后40动作也参与训练”是共同设置，不是OneDP独有问题。

## 损失范围怎么理解

把模型输出想成“50行，每行32个数”的表。机器人每次读取前10行、每行前14个数。直接蒸馏给50×14打分；OneDP给50×32打分。填充18维不发送给机器人，但参与模型内部计算和损失。不能仅凭坐标数断言它们主导了梯度。

建议第一项对照只统一**生成器的物理维**，明确按14个有效维重新平均。辅助网络的任务是估计当前学生完整分布，应先保留其现有拟合目标、分别记录物理维与填充维的误差；不要把“对齐学生监督”混成“同时截断辅助网络、改时间权重、只训前10”。截断辅助拟合和只训执行前缀均属于后续独立选择。

H50→只监督前10×14是另一项实验，最好两个方法同时比较。它不会自动把网络计算缩到1/5：模型仍生成H50，教师仍做10次动作专家前向。

## 当前效果与后续最少诊断

共同5565更新：直接116/368=31.5%，OneDP82/368=22.3%；原始N1=20.4%，N10=41.6%。二者用相同观察数据和冻结VLM，直接蒸馏能提升，说明这些共同设置没有阻止一步学生学习；仍不能仅凭此判定OneDP失败的唯一原因。

固定少量、任务均衡观察，记录学生生成器的前10/后40、真实14/填充18梯度；辅助误差按相同维度和噪声时刻分组；比较冻结学生下辅助多学几次前后，修正方向是否稳定。总fake训练误差下降不能代替这项判断。

当前OneDP的flow权重、归一化与辅助更新比都是方法相关切口，见[55号](55_DMD_STABILITY_RECIPES_20261026.md)。正式训练不自动跟随讨论修改。
