# 两种方法怎么训练、需要什么数据

用“机器人看见瓶子，生成接下来 50 个动作”说明。现有 π0.5 先从一团随机数开始，计算 10 次，逐渐得到动作块。我们希望训练一个学生，计算一次就生成可用的 50 个动作。

这里的“一步”是一次动作网络计算，不是机器人只动一步，也不是一次完成整回合。机器人执行完动作块、看到新画面后，还要再次调用策略。

## Consistency Policy：学会跨过生成过程

老师不更新。训练时拿一条示范的图像、状态、指令与动作块，给动作加入噪声；让老师走一小段生成过程。学生分别从这段过程的前后位置，跳到同一个生成阶段，要求两条路径给出一致结果。

官方 CP 的 CTM 可以指定“从哪个噪声阶段跳到哪个阶段”；训练还把两条路径送到最终动作处比较。它另有一项监督，要求结果接近数据里的真实动作，避免只学会彼此一致、却不会做任务。EMA 是“学生近期参数的平滑副本”，用来提供变化较慢的目标。

我们保留这些核心结构，使用 π0.5 现有流速度和动作训练接口。动作专家增加一个小的目标时间条件；原来的相机、语言、动作格式继续复用。优先保留 CTM 跨阶段训练，而非悄悄缩成只模仿老师最终动作的普通回归。

依据：[CP 官方损失](https://github.com/Aaditya-Prasad/consistency-policy/blob/eed0c465d3c1aa6dcf22f10e784df07dec06beac/consistency_policy/student/ctm_policy.py#L404)。

## OneDP：学会产生老师认可的动作分布

同一画面下，老师可能允许几条略有不同、都合理的动作路线。OneDP 不要求学生对每个随机数逐项抄一条固定答案，而是要求学生产生的这批动作，整体接近老师的分布。

随机版 OneDP-S 有三个角色：

| 角色 | 做什么 | 是否训练 | 正式执行是否需要 |
|---|---|---|---|
| 老师 | 判断加噪动作应往哪个方向变得更合理 | 冻结 | 否 |
| 学生 | 根据图像、状态、指令和随机数，一次生成动作 | 是 | 是 |
| 辅助网络 | 学生一直在变化，它跟踪学生当前会生成哪些动作 | 是 | 否 |

一次更新：学生先出动作 → 给动作加噪声 → 辅助网络学习这批学生动作 → 比较老师与辅助网络给出的调整方向 → 据此更新学生。辅助网络不是任务成功奖励模型，也不需要成功/失败标签。

原文还有无随机输入的 OneDP-D，训练更省一个辅助网络，但会减少动作多样性。本轮先做 OneDP-S，与现有随机 π0.5 更一致；不额外铺开第三条主线。[OneDP 正式论文](https://proceedings.mlr.press/v267/wang25ba.html)。

## 是离线还是在线？需不需要提前跑老师？

两篇原工作在这里都是离线策略蒸馏，不是在线 RL。训练时会即时调用老师/学生网络，但无需每次更新都运行机器人环境；模拟器主要用于最后的闭环评估。

| 数据 | CP | OneDP-S |
|---|---|---|
| 图像、机器人状态、语言指令 | 需要 | 需要 |
| 对应的专家动作块 | 原版监督项需要 | 核心分布匹配不强制需要 |
| 老师完整 10 步输出的预存配对数据 | 不是必需；训练可即时走局部老师过程 | 不是必需；训练即时查询老师方向 |
| 成功奖励、Q 值或 GRPO 优势 | 不需要 | 不需要 |

本轮已落实为TianxingChen官方的adjust_bottle / Aloha-AgileX Clean50；服务器已有可用转换结果，三相机、状态、指令、下一时刻绝对关节目标均已核对。50条、7,188帧、4,738个完整H50窗口；两种方法共享观测来源。当前无需重新采集推理轨迹，具体路径见05。

没有合适专家数据时，也可从原始 N10 模型在独立训练种子下生成一批数据。CP 的动作监督此时属于“老师伪标签”，应标清；不能把失败时执行过的动作自动当作专家答案。OneDP 的观测池可以包含失败状态，帮助覆盖学生可能遇到的画面。

已有 U/四噪声采集不仅有视频，还保存了原始三相机图像、状态、指令、归一化动作和执行动作，适合先验证数据/训练接口。用于正式训练时要按整条轨迹和实际种子拆分，不能把同一轨迹不同动作块分到训练和最终测试两边。精选图册不是完整训练集。

训练生成噪声、局部老师查询都可在线计算，不需要先储存庞大的 10 步轨迹缓存；是否缓存只由测得的读取/计算瓶颈决定。
