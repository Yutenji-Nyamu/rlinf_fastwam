# FQL接入π0.5直接蒸馏：固定老师方案

2026-10-25。研究与实施规划；尚未修改正式训练、启动FQL或采集。配套：[数据契约](47_FQL_TRANSITION_CONTRACT_20261025.md)、[采集预算与数据选择](48_FQL_COLLECTION_AND_DATA_MIX_20261025.md)。

## 结论与来源

ReinFlow的PyTorch FQL适合借损失、双Q和目标Q更新；模型仍用我们的π0.5。算法语义以[官方FQL](https://github.com/seohongpark/fql/blob/e8cd16eb490332924dfa2492097219f181765933/agents/fql.py)为准，PyTorch表达参考[ReinFlow FQL](https://github.com/ReinFlow/ReinFlow/blob/e722e151bed767f3ffef47527cf697f2358af55d/model/flow/ft_baselines/fql.py)。

本方案叫“固定π0.5先验的FQL适配”：原版还用FM训练多步行为模型B，我们固定已经训练好的N10老师，只训练一步学生G和Q。因老师不再拟合新采集动作分布，这是一项需要明确报告的差异，不称为原版逐项复现。老师和学生从同一权重开始并不矛盾：N10与N1生成结果不同，后者还会随训练改变。

本次拟由同一个N10老师采集，老师与数据的行为来源一致，因此固定老师是合理起点；它仍不同于原版持续更新B。

## 对当前直接蒸馏的改动

现有代码基于`worktrees/pi05-distill-20261021`，不是另写一套π0.5。

|接口|已经有的|本次拟加的|
|---|---|---|
|`rlinf/algorithms/pi05_distillation/model.py`|`Velocity`冻结VLM、仅训动作专家；老师原生N10；共享前缀缓存|增加独立`prepare_fql`，返回当前/下一观察上下文及Q特征；保持旧`prepare`返回值|
|`openpi_action_model.py::_build_prefix_cache`|已经返回`prefix_output、prefix_masks、KV cache`|复用原本被`prepare`丢弃的prefix_output，不另跑一次当前观察的VLM；下一观察仍需处理|
|`losses.py::endpoint_loss`|同观察、同噪声，老师10步与学生1步的H50×14归一化动作MSE|拆出可微学生终点，增加学生动作的Q项；老师目标无梯度|
|新的`fql_q.py`|EXPO有动作块Q接口可参考|任务条件共享双Q、目标双Q；不接Editor、熵温度或EXPO的20次Q更新|
|新的`transitions.py`|现有DemoWindows读SFT窗口|独立读取真实动作块转移；不能把H50窗口的第50帧冒充C10后的状态|
|新的`train_fql.py`|现有双卡启动、AMP、导出、完整恢复、精简评估|复用运行结构，新增Q优化器/目标Q/数据索引；与旧三种蒸馏入口隔离|

Q首版输入：冻结视觉语言前缀的有mask池化特征、归一化关节、前10个归一化动作、有效前缀mask和剩余动作预算。前缀已含任务指令；全局task_id另用于抽样和日志，不能用各数据目录内部重复的局部编号。池化方案是轻量起点，是否足够区分物体/任务须通过留出轨迹诊断。

学生仍预测H50。蒸馏监督H50×14，Q只评价实际交给环境的C10；不足10的末块按mask处理。采用现有归一化，不照搬ReinFlow对动作的[-1,1]裁剪。

## 一次训练更新

1. 均衡选任务，从该任务的真实转移抽一批`观察、执行前缀、奖励、下一观察、结束原因`。
2. 下一观察由学生生成N1动作，目标双Q取均值，构造`y = r + 0.99 × bootstrap_mask × Q_target(next_obs, next_action)`。这一支全部无梯度。本方案0.99按一次C10决策定义，不按机器人内部物理步定义。
3. 两个Q各自拟合y，取两头MSE的平均。ReinFlow写成两头相加，官方是整体均值；这里明确取平均，避免默默改变Q损失尺度。
4. 当前观察给老师和学生同一份新高斯噪声。学生最小化`α × endpoint_MSE − mean(Q1,Q2)`。此时冻结Q参数，但保留Q对学生动作的导数；不能把整个Q调用放进no_grad。
5. 更新目标Q；保存逐任务抽样量、奖励、TD误差、Q范围、端点MSE及两项学生梯度规模。部署只用学生。

这是固定数据上的离线训练；采集一次真实执行数据，并不等于训练期间持续在线RL。不要给失败轨迹的所有动作统一标“坏动作”：训练使用每段的真实奖励和后续价值，轨迹成败只是结局标签。

## 参数起点及依据

以下是待smoke的起点，不是已经验证的正式配置。

|参数|拟定值|依据/限制|
|---|---|---|
|基座与动作接口|原Sidney；三相机、绝对关节、H50/C10、N10老师/N1学生|当前直接蒸馏和C10评估|
|训练模块|冻结老师/VLM；训练学生动作专家及Q|本轮固定老师选择|

|Q|双头MLP，各4×512、LayerNorm；Adam 3e-4|官方FQL默认；输入改成冻结VLM特征，需核实际内存和收敛|
|目标Q/聚合|tau=.005，mean；1次Q/1次学生|官方默认与ReinFlow参考；不额外引入20:1|
|折扣|.99/决策块|宏动作MDP适配；不称原论文的物理时间尺度|
|α|10为首候选，记录MSE/Q及梯度量级后再定|官方默认并明确要求按任务调节，不能保证50任务通用|
|batch|有效全局384为目标；每卡192能否保留要测|新增下一观察前缀占内存；必要时以梯度累积保持有效batch，不能用旧峰值直接担保|
|数据抽样|先均衡任务、再均匀抽该任务转移|延续任务均衡；不默认把成功/失败改成50:50|
|预算/评估|拟先10预算轮；约10次评估，早期加密|实际转移数确定后重算；不沿用旧HF的55650更新|

若约23.3万转移、全局384，10预算轮约6070更新，仅为容量估计。无成功轨迹的任务单独标识：这些任务的Q没有正奖励证据；不因总回合数够了就声称Q可学好。

## 最少验收和结果边界

- 先验数据时序/终点奖励；再验老师、目标Q、学生的梯度归属及一次完整恢复。
- 确认α端点项、Q项、Q误差尺度，Q没有凭空快速飙升；这些只诊断实现，不能替代闭环成功率。
- 精简评估仍50任务×8，原生上限、原固定测试种子，无视频；拟用0、约150、300、600后按剩余预算分布至约10个点。
- 完整恢复保存学生、双Q/目标双Q、全部优化器/调度、RNG、采样器状态、固定基座/数据版本；推理导出仅学生。
- 若要判断“Q有没有用”，须有相同采集观察、相同更新预算的纯端点蒸馏对照。直接与现在HF观察训练的成绩相减，会混入训练数据变化；该对照只列规划，尚未排队。
