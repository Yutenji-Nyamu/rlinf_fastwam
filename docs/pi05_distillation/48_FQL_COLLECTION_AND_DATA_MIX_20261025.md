# FQL采集预算、成功失败与HF示范的选择

2026-10-25。用户希望先充分规划，约每任务100回合。以下是收敛建议，尚未启动采集或改变现有GPU队列。

## 数据怎么选

不是“只差失败数据”：HF目前有专家观察/动作，但没有显式reward、terminated、truncated和可直接使用的C10转移。此前已核50任务元数据及按铃原始/转换时序，详见[44号](44_FQL_OFFLINE_MULTITASK_DATA_20261025.md)。

|数据|强项|局限|首轮用途|
|---|---|---|---|
|新采π0.5成功轨迹|真实模型在本协议下的成功路线、修正行为；奖励/后继状态可直接记录|未必如专家干净，也可能有绕路|与失败一起训练Q，并提供学生/老师观察|
|新采π0.5正常失败轨迹|偏离、失误、卡住和未完成的真实后果|不能把每个动作都标为错误；全零奖励任务证据不足|与成功一起训练Q|
|HF专家成功示范|质量高，50任务均有成功示范，覆盖模型难成功的任务|时序/终点奖励要补齐，不宜直接混作C10真实转移|保留；当前老师已有其训练先验；首版不新增专家FM项|

**推荐首版Q用新采成功＋失败的统一转移集；HF继续保留。** 这使控制、奖励、观察和动作口径一致。成功数据没有哪种天然更好：专家更适合教规范动作，模型采集更适合教Q识别模型实际会遇到的后果。

结果标成success/failure/invalid，分别生成索引和统计，不复制成两份物理数据。初版不强行成功失败各半：任务均衡，任务内按真实转移抽样；记录长失败轨迹占比，避免悄悄改分布。若以后混入HF，先补转移与末帧，再作为独立对照；不是简单把全轨迹最后一行贴1就算原生奖励。

原始C10/N10最近完整小批153/368=41.6%，总体已有较多失败。这个全局平均不保证每任务96回合都会同时获得两类；0成功任务不无限补采，明确报告，后续再决定用专家补证据或改变行为策略。

## 固定采集方案

|项目|建议|
|---|---|
|环境/任务|RoboTwin2.0 Clean，沿用当前50任务表与各任务官方上限|
|行为策略|原始Sidney π0.5，N10；H50、C10、绝对关节动作及原归一化|
|回合数|每任务96=12批×8，共4800；约100且整除当前稳定批量|
|并行|每卡3个独立常驻worker×8环境=24；两卡合计48|
|采集内容|[47号契约](47_FQL_TRANSITION_CONTRACT_20261025.md)；仅决策边界数据，不录像或额外算信号|
|种子|新固定清单；与当前评估种子分离，同时检查native_retry后的实际种子；能核得的HF原始种子也排除|
|顺序|先所有任务一批，再轮转补至12批，避免长任务挡住全覆盖；模型在同配置worker中常驻|
|故障|沿用有限超时、留因、仅清自身进程、继续下一任务；同一任务连续两次同类故障后跳过余批并报告缺测，不无限重试|
|保存|每回合完整提交、已完成回合可续接；数据仍放/data，发布代码/配置/统计，原始图像及权重不进普通Git|

先只采N10，控制一个行为来源。N1混合能够增加学生易错状态，但本版先不悄悄加成另一个实验；如果某些任务需要不同覆盖，再单独扩展行为策略并标明比例。

## 时间与容量：用我们实际记录估计

读取旧扫描`chunk-sweep-sz1-g67-20261024/summary-raw-c10-n10-b0.json`及46任务的episodes.json：

- 双卡每卡3×8，无录像，全50任务尝试一轮约5868秒=97.8分钟；368有效回合。
- 有效回合平均提交485.2个模型动作点，最长1700；按C10约48.5个决策块/回合。这些是提交数，不是物理控制步。
- 96/8=12轮，按原速度约19.6小时；新增转移写盘尚未实测，计划两卡20–30小时、单卡40–60小时。相同故障任务/主机负载也会影响耗时，不能保证4800全部有效。
- 按每决策边界3×224×224×RGB uint8、T+1观察、不重复next_obs，4800回合约100GiB未压缩图像；动作与标记相对小。按100–150GiB工作容量准备，实际压缩比和I/O由首批测量，不能靠假定高压缩率启动。

22:50 Data余228.8GiB，现有两训练还在生成完整点。推荐先决策[约220GiB清理档](../maintenance/sz1_fql_storage_candidates_20261025.md)，再明确采集GPU。不能把228.8GiB全部当作新数据可占额度。

当前路由是1机3卡Dojo、4/5直接蒸馏、6/7 OneDP；3卡无RLT，4–7保持逐卡候补。本轮仅规划，没有自动占用0/1/2，也没有挪动或停止当前队列。若后续不改训练优先级，最自然是3卡Dojo结束后单卡采集；需要两卡20–30小时方案时，再指定可用卡对。

## 启动前应交付的具体结果

采集器实现与最小smoke、正式解析后的配置（不能用含旧32环境/视频值的未覆盖模板）、种子清单、数据字段重载验收、实际GiB/回合与吞吐。仅这些通过后排正式4800预算；本文件不是已经“打开采集开关”的执行回执。

数据回来后先报告每任务有效/成功/失败/异常、动作数和奖励分布，再按真实转移数计算FQL预算。无需预先保存海量老师10步答案，也不能仅因收了失败数据就保证Q或成功率提升。
