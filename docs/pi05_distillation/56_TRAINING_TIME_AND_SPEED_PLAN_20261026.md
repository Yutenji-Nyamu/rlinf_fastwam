# 直接蒸馏时间账与提速讨论

2026-10-26。本轮只读取正式训练，做了一次无CUDA的代表性CPU解码计时；没有给4–7卡挂profiler、改batch或改loss。

## 时间花在哪里

截至本轮快照，直接蒸馏7160步。启动以来训练阶段14.46小时、6次正式评估10.20小时，合计约24.67小时（不含最初约6分钟smoke）。**训练阶段约59%、评估约41%**。早期评估密集，所以这个比例不能外推整个50轮：后面点距更大。

训练阶段包括真正更新、加载、保存。7段启动/续训合计约29分钟，每次约4.1–4.3分钟；其余主要是连续更新。稳态约6.8–7.0秒/步，累计平均约7.1秒，保存等包含在后者。评估每次5745–6453秒，即1.60–1.79小时。

同快照OneDP6790步：训练阶段12.72小时、7次评估11.94小时；稳态约6.2–6.4秒/步。较少的老师调用被辅助网络训练和供数成本部分抵消，不能按“少9次老师前向”推断快10倍。

时间证据：队列事件、rank0指标时间戳与summary.elapsed_seconds。重启时间由首条指标减去更新估算；模型计算内部尚未做分项GPU计时，不能把所有余量都归因某一个算子。

## 一次更新实际做什么

1. 每卡抽192个窗口；从已在RAM的压缩图片里逐张解码576张RGB图，拼成约506MiB输入。**不是每次从磁盘重读整轨迹**。
2. 图像/指令/状态经过冻结视觉语言部分，建立观察缓存；同一观察的老师和学生共享这一缓存。
3. 老师动作专家做10次前向，得到同噪声的H50答案；学生做1次前向，然后反向更新动作专家。
4. DDP同步梯度、裁剪、AdamW更新。每10步写少量指标；每634步和评估边界保存完整续训点和推理导出。

因此，没有“老师重复把同一图片编码10遍”的冗余。当前冻结前缀缓存已经复用。老师的10次动作计算是直接蒸馏目标的主要必要工作之一。

## 具体发现及优先级

|候选|证据|建议|
|---|---|---|
|CPU解码与GPU计算重叠|当前主训练线程逐张PIL解码、np.stack；没有预取。3任务各1轨迹的192窗口小样，解码拼接**3.24秒**|首选：少量线程解码，提前准备下一批；只缓存1–2批，保持取样/种子/动作不变|
|更快attention|实际get_suffix_out/_build_prefix_cache强制eager；安装的Gemma分支确实据此走eager_attention_forward|其次：尝试SDPA兼容实现；固定小批前向与梯度对照通过再换。不能只翻开关后直接用于正式训练|
|编译固定形状动作计算|当前训练入口未启用torch.compile|单独试，计算预热成本和重编译；收益未测，不承诺倍数|
|减少训练进程反复重建|每次评估后重新torchrun、加载50任务数据/权重/优化器，约4分钟|有收益但小于秒级每步优化；保留长驻数据/训练状态需要处理评估显存腾挪，后排|
|保存开销|直接每点约4.81GiB恢复＋1.60GiB导出；634步保存间隔，完整段保存/等待残差较小|不是当前主要瓶颈；继续保留完整续训，不拆恢复分片|
|增大batch|当前每卡192；直接实占约67.3GiB，峰值分配64.55GiB；OneDP约75.8GiB，峰值72.61GiB|OneDP余量少，直接有些余量；先处理供数，再决定是否测更大batch|
|提前缓存老师答案|老师固定，理论可省在线10步|固定noise答案会减少随机目标多样性，且产生存储；属于数据预算改变，不作为第一项无损优化|
|全数据解码/缓存VLM前缀|RAM仍余约1.15TiB，但现4个训练rank已各约150GiB RSS|全量RGB约TB级，前缀KV可能更大；先用小预取队列，不再额外复制整个数据集给多个worker|

3.24秒来自独立CPU小样，既非同一训练更新的分段profiler，也未覆盖全部任务，**不能严称它占整步46%**。但量级已经足够支持先试供数优化。PyTorch也建议异步供数、必要的锁页内存和减少CPU/GPU同步：[官方调优指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html)。

实施预取时，优先线程共享现有RAM记录，防止多个进程各复制约150GiB数据。窗口索引由step/seed确定；预取不得消耗模型训练RNG，恢复时可丢弃预取结果重新生成。小队列大约每rank新增0.5–1GiB原始图像，不需要全数据解码。

## 收益怎么衡量

全55650更新中，每步真正省1秒，就省约15.5小时。相比之下，即使消除全部十来次4分钟重启，也只有约一小时。应以“同一批窗口、同loss、同精度和梯度，稳定窗口/秒提高多少”为准，不以显存塞满为目标。

后续若批准：先做有限分段计时→CPU预取对照→attention候选；各自单独验证。正式评估已经无视频、无逐动作信号，一轮约1.7小时主要是闭环仿真；进一步减少评估点/回合属于实验预算变化，另行讨论。
