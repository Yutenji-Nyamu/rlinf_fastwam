# 固定老师多任务FQL：效果退化与数据核对

2026-10-27。本轮不是“还差一点”：四个完整点为11/368（2.99%）、12/368（3.26%）、6/368（1.63%）、2/368（0.54%）。同协议原始N1为75/368（20.38%），N10为153/368（41.58%）。已按用户授权收束，保留完整1130点、此前282/565及采集数据，不自动删除恢复材料。

## 通俗机制

学生同时做两件事：复制老师动作、让Q评分更高。Q不是实际成功率，而是从离线记录学习的“未来还能拿几分”预测。这个任务每局只在第一次成功给1分，之后终止，所以真实折扣累计回报不可能超过1。

日志显示：Q对数据动作的平均估值从约1.3升到2.24，对学生动作给到约2.54；已经明显偏高。学生可能学会让这个不准的评分器满意，真实执行反而变差。估值偏高是直接证据；具体多少退化由Q引起，还需单独移除/调弱Q项的对照，不能把推测写成完整因果证明。

## 数据不是全失败，也没有发现终止边界写错

完整检查4408条轨迹、46个任务、216842条转移；1759成功、2649失败，轨迹成功率39.9%。只有1个已采任务没有成功。全部记录满足：观察数量=转移+1、终止mask最后为0且此前为1、整局奖励和=0或1并与成功标签一致。奖励转移仅1759/216842≈0.81%，任务均衡抽样后训练批平均奖励约1%–2%。稀疏奖励和长决策链增加了Q学习难度。

这些检查排除了“奖励全零”“终止后仍然bootstrap”等具体疑点；不能凭字段正确证明图像表征足以判断成功、Q已校准，或数据覆盖了学生产生的新动作。

## 参考实现与本适配的关键差别

1. 官方FQL同时训练行为流模型；本版冻结已经SFT的π0.5老师，只训练学生与Q，是事先约定的变体。
2. 官方明确alpha需要按环境调整。我们的alpha10沿默认，是初始值，尚未对机器人多任务尺度标定。当前端点约束比较H50，Q只看执行前C10，两者作用范围也不同。
3. 官方使用有界动作并在Q查询前裁剪到[-1,1]；π0.5原生归一化不是这个动作界限。抽样归一化动作约40.6%在[-1,1]之外，不能直接照搬裁剪，否则会破坏合法动作。需要按原生单位研究Q对动作的可靠范围。
4. 本版Q使用冻结VLM的平均特征＋状态；没有单独训练视觉编码器。细粒度成功几何能否在这些特征中区分，现有日志不能回答。

优先排查顺序：Q预测与真实折扣回报的校准、学生动作相对数据的偏移、alpha与执行段约束；再考虑Q预热/更新比或表征。新单任务队列先保留已smoke的五种方法，明确这是适配后的基线，不把未验证修复混进去。

依据：[FQL官方说明](https://seohong.me/projects/fql/)、[固定版本损失/默认参数/裁剪](https://github.com/seohongpark/fql/blob/e8cd16eb490332924dfa2492097219f181765933/agents/fql.py)。本地实现：`train_fql.py`、`fql.py`、`transitions.py`。当前配置学生最高2.5e-5、Q3e-4、alpha10、目标tau.005、每决策gamma.99；随机状态/恢复预算没有在暂停恢复时改变。
