# 当前实施规划：沿用OpenDW，每10轮补采并更新

2026-10-08讨论收敛版。替代上一版“可同时补KIR/历史/新loss”的默认范围；旧版完整保存在[归档](archive/20261008_before_chunk_only_cycle/PLAN.md)。本轮不实施、不启停训练。

## 继承项与取舍

原始预训练π0.5从RL第0轮开始，沿用OpenDW及lift_pot RM。策略总预算仍以200轮为参照，N64/R8/G8、512条/轮、C32/384、WM B16及每10轮保存/原生评估保持。只用3机物理4/5卡，6/7不动。

chunk成功/结束与现有loss保持；不加块内截断、不改成新的轨迹长度归约；不加KIR、不改OpenDW历史输入。一个条件图指一个时刻的三相机拼图，不是只剩一个相机。

## 采集与训练预算建议

| 阶段 | 原生新采集 | 训练用途 |
|---|---|---|
| 初始适配 | 原始π0.5采150条训练＋32条固定留出 | 原生同步三图/动作训练WM，主图/原生标签训练RM；固定留出不训练 |
| 每10轮策略RL后 | 当前π0.5新增100条训练轨迹 | 以新数据为主，可混50条已有训练轨迹；同一清单分别供WM/RM使用 |
| 最终第200轮 | 原有保存/原生评估 | 本轮后不继续RL时，无需再做一次无人使用的WM更新 |

这些是单任务起步建议，不是论文规定。150来自论文初始每任务量，100是后续1000条/10任务的平均。旧128条初始采集方案仍在归档，不与本版相加。成败自然保留，不筛种子凑50/50。

200轮策略＝20段×10轮；每段5120条想象轨迹，总计102400条。第10至190轮补采19次，共2050条原生训练轨迹；另加固定留出32条＝2082条。既有32条/次的原生策略评估另计，固定测试seed不训练。若以后减少更新次数或改变预算，应明确改实配，不通过暗中筛样或额外循环实现。

## 一次性实现

1. 在原生执行入口记录每条实际提交命令、同步command state、原生success/done；图像保存起点、每4条命令后三图及终点，足以配成C32/9帧。只在存图时增加采集，不改变原策略执行频率。
2. 薄的14D数据读取/预处理适配，使用现模型的归一化、prompt和图像拼接；复用OpenDW trainer/model/loss。保持现用统计，不因新增一小批数据就重算统计改变动作含义。
3. 按episode/seed先分训练和固定留出，再切窗口；复用原生评估执行器但采集用独立seed。
4. 保存/导出的WM仍由现服务读取。一次少量合同样本与一次完整optimizer更新足以先验收接线/峰值，不反复长smoke。

## 正式阶段顺序

`原始π采初始真实数据 → 微调现用WM/RM → 策略RL 10轮 → 保存卸载 → 当前π原生补采 → WM训练 → RM训练 → 加载新模型 → 策略继续10轮`

- 同一个GRPO采样批次中WM/RM版本固定；在阶段边界切换。
- 策略保留权重及优化器/学习进度，不每10轮重置。WM/RM从上次模型继续适配，不反复回到最初权重。
- WM和RM共享采集数据，但分别训练：WM学动作之后会发生什么，RM学图像是否已经成功。顺序执行即可；无需联合loss或多模型并行调度。
- 每次补采的历史混合从既有训练split读取，50条旧数据是本轮建议；不触碰留出集。不必每阶段把所有历史数据全训一遍导致单阶段成本不断增长。
- 原生阶段的RM逐时刻标签来自RoboTwin；成功回合开头仍为0，不把整条成功视频都标1。

## WM训练量与两卡使用

WoVR正文没有可直接套给OpenDW的WM梯度更新步数。RLinf公开冻结WM示例配置的max_epochs=1000是策略轮次上限，也不是WM epoch。OpenDW通用配置num_epochs=5；可作为初始训练预算候选，不是已验证最佳值。

WM训练步数约为：训练窗口数×epoch数÷有效训练batch。有效batch由每卡microbatch、训练进程数、梯度累积决定；与WM推理B16独立。举例：100条每条完整384动作，若只取不重叠C32片段，最多1200段；5遍约6000段次，有效batch8时约750次更新。这只是量级算例；若采用stride4重叠窗口，训练样本会更多，不能仍报750步。实际必须按adapter的窗口清单计数。

不提前保证两卡能容纳默认全参数训练。实现时先测一次完整更新，确定可用batch与耗时，再决定是否需要官方现成的内存优化。资源边界仍4/5，不因内存不足擅自借6/7。RM沿已有轻量训练器和资源参数运行，GPU占用不需要与WM反向同时叠加。

## 数据与运行保持简洁

完整轨迹写一次，按窗口读取；可沿用现成的数据加载缓存，不加单轨迹缓存限制或每步整轨迹重读校验。一次短训同时记录数据等待和完整step耗时，确认新增记录/读取没有明显拖慢流程。

验证复用32条固定留出中的少量片段、现有RM指标及既有原生策略评估。不扩为完整论文视频质量基准；日志查询超时不能触发停训。只复用现有实验owner与RLT候补边界，阶段卸载期间不归还RLT，整项退出后才候补。

除首次WM训练batch/速度与小数据效果需要实测，采集字段、接口和阶段接线已清楚，没有新的接口选择需要用户逐项决定。
