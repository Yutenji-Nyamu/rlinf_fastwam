# 这轮方案：按现用OpenDW做一个清楚的更新循环

2026-10-08继续讨论，按用户最新取舍修订。上一轮完整WoVR讲解保存在[归档](archive/20261008_before_chunk_only_cycle/WOVR_EXPLAINED.md)，本页只讲当前要做的事情。本轮未实施或改训练。

## 1. 平时练策略，隔一段修正模型

平时：π0.5出动作 → OpenDW预测画面 → RM给0/1 → GRPO更新π0.5。

每10轮：保存当前策略 → 原生RoboTwin执行并记录 → 用真实数据分别训练OpenDW和RM → 加载更新后的模型 → 策略接着练。

“真实”指原生物理仿真的实际结果，不要求实机机器人。10轮是用户看当前曲线得出的选择；512条/轮，因此每段5120条想象轨迹。策略总预算仍以200轮为参照。

## 2. 这轮不需要补齐WoVR所有功能

- chunk照旧：成功所在动作块保留，后面不再执行；不在32个动作内部拆分奖励/损失，不改现有平均方式。它是当前chunk级方案，不宣称逐项复现论文loss。
- 历史照OpenDW：一个时刻的条件图包含三台相机。下一段预测用当前图和未来32条动作；不会额外读取回合开头和过去多个时刻。这个模型已经这样训好，我们沿用。
- KIR不加：从中途起点练是可选方法，不是更新WM所必需。当前reset保持。

“把轨迹保存到硬盘”和“让模型一次读多时刻历史”是两件事。我们需要前者来形成训练样本；不需要为了保存数据而给模型增加历史输入。

## 3. 一条保存好的真实轨迹怎样变成WM训练数据

例如记录起点画面、接下来的32条实际命令，以及第4/8/…/32条命令后的画面。训练时，把起点图和32条命令给模型，要求它预测那8张实际发生的后续图。

因此方向很清楚：每条命令和控制状态都保存；三台相机在相同动作时刻保存；记录原生成败和回合边界。可以每4条命令存一次三图，动作不跳着存。无需另训state预测器，也不要求只收成功轨迹。

固定评估seed不训练，采集另用seed。旧RM数据缺腕图和完整动作，新采集时一次存齐即可；不需要人工补画面或人工逐帧标成败。

## 4. 采多少，官方到底说了什么

[WoVR §5.2](https://arxiv.org/html/2602.13977v1#S5.SS2)写：每个10任务suite先1500条，即每任务150；策略改善后再采1000条，平均每任务100，实际只更新WM一次。没有规定每10轮更新，也没有给可直接用于OpenDW的WM优化步数。

[RLinf公开策略配置](https://github.com/RLinf/RLinf/blob/0067f7d5ce525c18bda439ed8dbb638abafd6a06/examples/embodiment/config/wan_libero_spatial_grpo_openvlaoft.yaml)是N64/R16、max_epochs1000，属于冻结WM示例，不是论文全部实验的执行日志。我们仍用N64/R8、200轮，不追着默认值扩预算。

建议单任务初始采150条训练，另外32条固定留出；以后每10轮补100条。100新轨迹可混50旧训练轨迹，避免只学最新动作，又不必每次把全部历史都训练一遍。

如果跑200轮，第10至190轮共有19次补采，总共2050条训练＋32留出；原生策略评估另计。明显超过论文每任务平均250条，因为我们选择反复更新。该预算是讨论建议，未启动。

## 5. WM究竟训多少

“采多少条”和“每条反复学几遍”不同。OpenDW通用训练配置默认5个epoch，即对训练样本集合走5遍；可以作为起始预算候选，不代表WoVR指定5遍或必然收敛。[默认定义](https://github.com/dexmal/opendw/blob/e33befa8005a1585e0140dbf464566e90bc79aa1/dexbotic/exp/base_dw_exp.py#L97-L124)

一条长轨迹可切出很多C32训练片段。实际更新步数取决于片段数、重复遍数和有效训练batch；与策略10轮、WM推理B16都不能混算。第一次完整微调短测再确认速度/显存和适合的训练量，不提前报未经实测的分钟数。

## 6. RM可以一起更新，但不是合成一个模型

同一批数据有两种答案：动作后实际画面给WM学；画面是否成功给RM学。放在同一离线阶段分别训练，顺序运行就行。RM复用现有小分类器训练路径，使用真实标签和原有训练数据；不拿WM自己生成的成功标签教自己。

## 7. 模型相关格式全部按现用权重来

保持14维绝对命令、当前mean/std、当前三图resize拼接和C32。官方默认训练示例的32维、相对动作和另一套缩放不用硬套。

改数据读取和模型配置，使官方OpenDW训练器接收到现模型熟悉的格式；复用其计算、训练、保存恢复。现用模型结构不变，现用权重可以作为续训起点。

## 8. 仍然只安排两卡

策略RL沿GPU4策略、GPU5 WM，N64/R8与B16保持。采集、WM微调、RM训练在阶段间复用4/5。WM反向的batch另测，不保证推理B16直接训得动；6/7不借用。

阶段切换保存进度后卸载，不把π0.5每次重置。RLT只在整个优先实验退出后候补。无需新的长期守护，数据与模型入口顺序衔接即可。
