# RynnValue 数值头：离线进展诊断

2026-10-05。用户授权尝试数值奖励。当前范围是离线诊断，尚未把数值接入 GRPO，也不据此直接启动正式训练。此前语言 `Success: Yes/No` 在专家控制视频上全部判 No；本次检查同一模型的独立数值输出是否仍含有可用的任务进展信息。

## 具体读什么

固定模型 `Alibaba-DAMO-Academy/RynnValue-8B@8738c5e4`，固定官方代码 `10e0d333`，沿用已修复的全模型 BF16 加载。每条输入仍是任务文字、机器人/相机说明和主相机历史中的 K8 帧，320×256；与现有 WMRL 接口一致。原 HDF5 图像的尺寸和解码合同在数据回执单列，不能把缩放后的输入称原尺寸。

执行官方 `rynn_infer/inference.py` 的 `run_batch` 函数：`outputs.value.pred_value` 取每条视频最后一个绝对值槽。固定官方提示明确要求预测完成任务还需多少秒，**越低应越接近完成**；因此它是模型预测的剩余时间，不能当作本场景已校准的秒表、概率或成功判定。另保存 8 个绝对值槽和 7 个相对值槽用于分析，但主结论使用每个独立前缀的最后绝对值，避免不同历史范围混淆。数值 forward 不生成 Analysis 文本。

`process_episode` 没有 fps、时间戳或动作数输入；回执中的 `frame_indices` 不写入模型提示。模型主要凭画面和任务推断距离，不能据其输出声称知道本轮真实经过多少秒。相对头询问相邻画面间的时间差，不能直接把相对输出当 Success 或固定一步的奖励。

单位不能只依据提示语判断。[论文 §2、§3.1.2、§3.2.3](https://arxiv.org/html/2608.09853v1) 进一步说明：绝对训练标签是 $\max(0,t_G-t_i)$，按时间戳得到秒数，并非每条轨迹归一化到 $[0,1]$ 或百分比；绝对范围 $[0,512]$、相对范围 $[-256,256]$ 用 256 个 symlog 区间表示。推理先求 symlog 空间的加权均值，再经 symexp 返回时间量。固定 HF 配置也为这两个范围、`support_transform=symlog`，与论文一致；本轮未新增核对完整训练数据生成及 tokenizer 反变换源码的服务器回执。图表因此标记 `Predicted remaining value (raw; lower = closer)`，不把例如 0.34 的模型估值读成经过本场景标定的“还差0.34秒”，也不据此设成功阈值。

官方依据：[固定推理入口](https://github.com/alibaba-damo-academy/RynnValue/blob/10e0d333f5f3811d0d130587e50f1faf48da49e5/rynn_infer/inference.py)、[固定模型权重与自定义头](https://huggingface.co/Alibaba-DAMO-Academy/RynnValue-8B/tree/8738c5e4ce4418ea0266e9fbeffae0eb9bbb230e)。函数 AST 来自已核 SHA256 `2590fd6c9597f47b3e82fadce453b295ef54d547ea4341e8a42d1b354f6c1670`；探针只包装输出记录，不改官方 forward 参数或磁盘模型。

## 少量数据与判读

数据准备脚本已实现：取既有 clean50 清单顺序的前 16 条专家，每条 8 种输入，共 128 条；没有按 Rynn 得分选择轨迹。

| 输入 | 希望检查什么 | 证据边界 |
|---|---|---|
| 0%、25%、50%、75%、100% 历史前缀，每段均匀 K8 | 越往后，最后剩余值是否总体下降 | 五个点分别重建历史，不把一个完整视频内部槽误当独立前缀 |
| 末帧重复 K8 | 同一末画面有无历史时是否判断一致 | 0% 前缀已是初始画面重复，不重复算一份独立负样本 |
| 整段倒放 | 输入退回起点时，数值是否回升 | 合成时序对照，不是物理执行失败 |
| 正向后退回起点的 K8 序列 | 是否只见到后面的帧就一律降低 | 合成对照，同样不标物理失败 |

本轮找到 CP70 的 32 条原生评估对应视频资产，但视频以 16 环境拼图保存，画面 reward 叠字均为 0，`ignore_terminations` 下 termination 也不能用作逐环境的成功标签。尚未还原与每个窗口严格对应的 simulator 成败回执，**本轮不纳入真实成功/失败集合，不报告 native AUC**。画面上的 reward=0 不代表该条物理失败；也不能把总成功率拆成自行指定的单条标签。

因此本轮可以回答“专家进展和合成退回是否有数值信号”，不能回答“真实成功与失败是否可靠可分”。专家 clean50 来自原数据采集流程的成功筛选，不能冒称本轮新跑了物理验证；倒放、退回和静止也不冒充真实失败。

逐专家报告前缀比例与剩余值的 Spearman 相关、初始减终态的差值、相邻下降数；负相关和正的初末差值是期望方向。静止、倒放、退回对照并列，避免把“时间过去了”误认成真实进展。即使这些对照通过，OpenDW 生成画面的域差异与奖励利用仍需另测。

## 并行与隔离

只借深圳3物理 GPU4，GPU5–7 的补占任务保持原状。数据由 RLinf 环境用 HDF5/cv2 预导出 NPZ，Rynn 子进程仅需 numpy/PIL/torch，不临时安装 cv2/h5py。

先做 CPU 输入/特殊槽检查，然后 K8/B1 的两个参照与 B16 同样本对照；正式数据按完全相同 token 长度分桶，最大 B16。记录 B1/B16 数值误差、初末方向是否改变、真实尾批、forward 耗时和 allocated/reserved 峰值；浮点差异如实保留。显存/吞吐是本次数值路径实测，不能拿此前文本 Success 的 5.35 clips/s 直接代替。

本次不改旧 WM owner、GRPO、保存/评估频率或已有 CP70。诊断结束同步 offload，再由既有单卡借还入口恢复 GPU4 的 RLT。启动/借还回执和结果追加到下节。

## 图像通道复核

本次数据链为 HDF5 JPEG → `cv2.imdecode` → 320×256 缩放 → `PIL.Image.fromarray`，沿用 reset 和前轮 Rynn 控制测试，未额外交换 R/B。这不是仅凭“cv2 通常返回 BGR”就能判断正确与否：RoboTwin legacy 数据把 RGB 数组直接交给 `cv2.imencode`，相同的无交换解码才能恢复原数值；新标准数据含 `XPL-RGB1` JPEG 标记，应走官方识别解码。背景见[已有接口复核](implementation_review.md#reset-jpeg颜色)。

已有 `build_reset_data.py` 对这套 50 条 reset 初始三图拒绝新标记；前轮 `prepare_samples_remote.py` 对相同 16 条专家的 K8 采样也逐帧检查无标记。本次服务器只读补查实际选中的 419 张原 JPEG，`XPL-RGB1` 为 0 张，保持现有 legacy 通道合同，没有额外交换 R/B。

## 执行结果

**数值头确实有进展信号，但 reset 的重复帧起点需要处理，尚不直接上线奖励。** 深圳3 GPU4 于 20:03:22–20:04:54 完成 128 条离线输入；`engineering_passed=true`，无生成文本，无策略或 WM 训练。全部帧/输入哈希和输出保留在 `rynn-numeric-v1/run/result.json`，SHA256 `15cd0071b06b55c9fbb3bc27284deb9220881c5932bc6befc4a4783fb7504c88`。以下均是原始预测数值，不设成功阈值。

### 同一末帧、不同历史及合成退回

| 输入 | 数值中位数 | 配对结果 |
|---|---:|---|
| 完整正常专家历史 | 0.304 | 基准 |
| 同一个终态画面重复8次 | 0.103 | 16/16 比正常历史低；同末图差值中位数0.199，范围0.035–0.562 |
| 倒放专家视频，末图为初始 | 6.267 | 16/16 比正常终态高；配对增加中位数5.966 |
| 先正向推进，末帧退回初始 | 5.433 | 16/16 比正常终态高；配对增加中位数5.020 |

退回输入与reset有相同的最后初始画面，却有13/16比重复reset高，差值中位数3.231。这证明输出明显受历史影响，不能只按最后画面解读。倒放/退回方向符合预期，有助于排除“序列越靠后就机械降分”的简单问题；它们仍是合成时序控制，**没有测出真实物理失败识别率**。本轮 native 成功/失败标签不可用，AUC保持null。
