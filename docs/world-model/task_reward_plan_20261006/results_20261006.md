## 显存换时间

- RM已缓存预处理图像到GPU，global64，micro32/64实测后选择64。本任务同样64张前反向23.03ms→12.65ms，约缩短45%；pilot之前的17%是另一份小数据实测。GPU缓存推理256图测试选batch256，纯网络吞吐约2.47万图/秒，不包含WM生成/HTTP/读图。
- RM训练Torch峰值分配2.17GiB、预留5.08GiB；整段训练只有约5秒。两卡训练或再扩大global batch对本次总耗时帮助很小，global变化还会改变优化过程。
- 原生采集GPU4显存中位/峰值均约29.28GiB，317次GPU利用率抽样均值16.76%、中位0%、最大100%。这支持“间歇等待、存在资源余量”，不能只凭抽样确定所有等待发生在哪里。
- 源码证据：当前`robotwin/envs/vector_env.py`使用一个ThreadPoolExecutor并发step；reset在`global_lock`内，初始化和get_obs也有逐环境循环。因此N增大并非所有环节都自动加速。
- 下次确需补数据，先短测N32×4，仍总128回合，同模型/seed/动作上限；比较每回合墙钟时间和峰值。若主要受单进程仿真/reset限制，再试两张卡各N16或独立环境worker。不是先把显存填满，也不预告线性翻倍。本次已完成，不为测速重采128或改动RLT。
