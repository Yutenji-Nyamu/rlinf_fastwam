## 输入先对齐，规模保持小

clean/rand是第一项，还需对应同一task_config、物体/布局范围、头相机与裁剪、RGB范围、缩放及标签时刻。当前OpenDW拼图为384×320：上方主相机256×320，下方两腕各128×160。RM用拆出的主图，不能把三视角拼图整体当成主相机；原生图经过同一裁剪/缩放后再送ResNet。[接口审计](../robotwin_pipeline_20261003/interface_audit.md)

这些是固定预处理的对齐，不要求先新建WM训练集。背景很像、同为clean仍可能出现手指位置偏移、物体变形、遮挡变化；恰好这些小差别会决定“碰到了没有”。因此保留一次小抽查即可，不能把域名对齐当作精度保证。

## 三份小结果

1. **原生验证/测试：**报告TP/FN/FP/TN与阈值，对照公开任务RM（如有）；数据划分见[data_recipe.md](data_recipe.md)。公开RM不是标签真值。
2. **整回合检查：**在留出回合的已记录时间点上顺序打分，检查首次给1是否早于原生首次成功、失败回合是否被提前判成。当前线上一个C32动作块看8张未来主图，最多384动作即最多96次判分机会；单图误判会累积，不能用逐图accuracy代替轨迹假成功率。没有对应图像与真值的中间时刻不补造标签，应说明覆盖范围。
3. **约32段OpenDW短片：**优先复用现有输出；16段固定随机抽样，16段覆盖高/低分和阈值附近，分开记账。审阅者看画面标“明显完成/未完成/看不清”，尽量先隐藏模型分数。后16段用于找问题，不能合并计算有代表性的总体准确率。

原生模拟器的标签只对真实轨迹负责，不能无条件复制给生成轨迹。OpenDW可能画成不同结果；看不清不能强行标0。抽查目的只是排除明显域差或假成功模式，不以32段宣称所有生成结果都可靠，也不先要求几百段大评估。

## 接回什么，保持什么

新RM封装仍输出现有接口需要的批量帧分数；接口测试确认shape、RGB、finite及保存/加载一致。它替换旧ResNet＋T5分类器内部，不改变OpenDW三视角生成、π0.5动作、GRPO分组和actor优化。原函数可保留instruction参数兼容调用，纯ResNet不使用它。

第一次接入继承当前首次越阈值给一次1、C32块末结束、后续mask和384动作超时的语义。块内任一帧越阈值的规则要在整回合误终止检查中评估；如果确有闪现假成功，再单独讨论连续帧确认或短历史，不静默改变reward/done。

新任务需配对应reset包、任务指令、RM权重、冻结阈值与同协议原生评估。小模型成本预计低，但只在执行时测batch/峰值后确认；复用现有批队列、卸载等待和资源记录，不新增常驻协调进程。

## 结果如何决定下一步

| 看到什么 | 下一步 |
|---|---|
| 原生和生成都能区分，未见成片假成功 | 可进入独立接入smoke；是否正式仍按实际结果判断 |
| 原生某类近成功负例经常误判 | 补该类真实标签，继续同一个小ResNet |
| 原生好、生成模糊/变形图容易误判 | 先定位裁剪/画质或生成域偏差；少量补对应样本，不盲目换大模型 |
| 判断取决于“刚才是否碰过”，单图看不出来 | 再借WMPO短历史输入，届时另列实现和开销 |
| WM把实际失败动作画成视觉成功 | 单换RM无法修复动力学；留原生对照，后续讨论WM覆盖/训练 |
