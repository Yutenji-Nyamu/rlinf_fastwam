# GAD新增时间来自哪里

2026-11-01，代码路径gad.observe、Velocity.endpoint、train.py和实际逐阶段日志。

每次更新对同一批观测做四种噪声的师生配对：老师每份5次动作专家前向，学生每份1次，因此新增4×(5+1)=24次**合批动作专家前向**，都是no-grad。每卡224个窗口一起算，并非逐条循环；K4按四个224合批顺序执行，共用同一视觉语言前缀，未重跑24次视觉语言模型。普通端点目标仍另用原来的5步老师/1步学生及学生反向传播。

当前Direct实测整步约8.2秒：

|环节|时间|含义|
|---|---:|---|
|取下一批等待|0.007–0.008秒|8线程解码与GPU训练重叠后留下的等待，不是CPU准备总共只花这些时间|
|预处理＋观察前缀|约3.55秒|图像/指令的模型输入处理与冻结视觉语言前向，原本就需要|
|新增GAD信号|约3.49秒|4份噪声×老师N5＋学生N1，再算标准差、距离、排序权重|
|普通学生更新段|约1.09秒|含原端点训练目标及反向传播；不是GAD新增|
|优先级更新|约0.001秒|小表刷新，远小于神经网络前向|

3.49秒约占**新整步**43%；按同次计时扣除新增信号是约4.7→8.2秒，增幅约74%，这只是阶段扣除估算，不是另外做过相同GPU条件的开关对照。四噪声相当于用更多计算换更稳定的信号，显存用满不代表免费计算。

DMD/MFD每次学生更新前有5次辅助更新，但K4信号只算一次并复用，没有为辅助5次重复算K4。端点求解沿用已验收原生采样器，其内部链/概率记录可能有额外小开销，本轮未单独测量，不将其宣称为主要瓶颈。逐阶段profile有同步开销，也未做开关对照。

想大幅减少这3.49秒，最直接的是降低信号刷新频率或K值；这会改变GAD设置，应作为下一版对照，当前正式训练保持原协议。复用视觉语言前缀、8线程预取已实现，优先级排序不是目前主要耗时。
