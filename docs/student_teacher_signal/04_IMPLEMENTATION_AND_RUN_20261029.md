# G族四噪声＋师生距离：实现及本轮运行

用户已授权实现、并发短测和正式采集。卡位按最后指示为1机3卡；若他人的图形/计算任务仍在，有限等待其退出，不清理他人进程。

## 沿用已成功代码

以`pi05_policy_eval/run_batch.py`的B32/C20双模型加载、种子、执行和完整录像为基础，仅新增`teacher_shadow:true`。Clean CP140执行，Uτ3 CP70在同一个当前观察及**同一份实际主噪声**下旁算。仍N10/H50/C20、200动作、32回合，且保存旧U10/5。

四噪声复用`pi05_u_video/noise_samples.py`。主样本保持原始B32推理；额外3×32份噪声在独立随机上下文中合批。启动时用同一批输入测试额外B96与两批B48，记录实际耗时及峰值，选择通过显存约束的较快方案。模型/仿真并行不能混为一谈：环境保持32，四种噪声不等于4环境。

这两个方案只影响旁路额外噪声的计算批形状，主执行动作及下一次随机状态必须完全不变。老师使用主噪声的最终实际dtype，不能使用另一次随机采样冒充同噪声。

## 采什么

每次当前观察保存三相机图、状态、指令；学生4份/老师1份完整预测、噪声、真实14维差值和RMSE、四噪声分散度、旧U、active/前后动作计数/成功状态。主模型返回的环境动作与实际提交的float32动作均可追溯，沿用G族原执行精度。

沿用完整25Hz头部视频、终止末帧、控制日志与左右臂投影映射。附加记录均不改变机器人动作。本轮是一条弱策略轨迹上的旁路比较，不实际接管。

`validate_shadow.py`从原数组重算两条曲线，核对共噪声、无接管、执行前缀及全部视频首末覆盖/末帧可读，并导出小`signals.csv`。未执行的预测尾部不进入执行曲线统计；视频映射继续标注为控制器路径投影。

## 已有检查和本轮停止条件

- CPU测试覆盖真实14维、同噪声零距离、96/48样本顺序、主输出/随机状态不变；和FQL共13项通过。
- GPU启动前复查物理卡。启动短测检查主动作与随机状态完全相同，再做一批32真实回合；验收批计入正式预算，不重复采集。
- 单批最多3600秒、无进展900秒；仅清理本轮唯一token的进程。目标卡忙最多等待4小时，失败留回执，不无限重试。
- 大材料放Home；Git仅源码、配置、并发记录、summary与小曲线表，原图像/视频/大数组不上Git。

部署与结果根目录均为本轮`fqlfix-shadow-sz1-20261029`；实际通过情况、并发速度、成功数随后以回执补充。

## 实测并发与启动修复

32环境，额外三噪声共96样本：B96单批2.56秒、峰值27.51GiB；两批B48为2.64秒、峰值20.75GiB。选B96；这是模型旁路短测峰值，不含后续32套仿真和录像。主执行动作、后续CPU/CUDA随机状态完全一致，教师与主学生的实际初噪声相等。

首个无环境预检发现：输出环境动作在CPU，不能用它的device.index保存CUDA随机状态。改为按原始模型噪声的设备fork；并让普通遥测也返回经过dtype转换的初噪声，不额外开启教师的U支路。该失败没有有效回合，原日志保留；补充回归测试后重启同一3卡。未终止他人任务。

验收和正式32回合是同一批；中途记录以本轮归档为准。完整视频/原图像/预测数组在服务器Home，本地和Git保留轻量结果、配置与曲线表。
