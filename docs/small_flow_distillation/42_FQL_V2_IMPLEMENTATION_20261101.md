# FQL v2：目标双Q取小值，学生Q项归一化

2026-11-01用户授权实现、双卡短测、推送并接到更早结束的正式队列。由已验收FQL-fix复制，独立分支 `codex/fql-v2-20261101`、独立服务器源码；旧实验代码与配置原样。

## 两处方法变化

1. 训练Q的目标为 `r + gamma * bootstrap * min(target_Q1, target_Q2)`。成功与动作上限终止仍令bootstrap为0，奖励只发一次。
2. 学生仍使用两Q的平均数 `q=(Q1+Q2)/2`。目标改为 `30*MSE - stopgrad(1/max(mean(abs(q)),1e-6))*mean(q)`。先逐样本平均双Q，再取绝对值求batch平均；双卡共同汇总分母。不是把所有Q值截到0–1，也不是把学生目标里的两Q改成min。

依据：[FQL官方固定源码](https://github.com/seohongpark/fql/blob/e8cd16eb490332924dfa2492097219f181765933/agents/fql.py#L20)，分别对应 `q_agg` 和 `normalize_q_loss`。归一化的尺度停止求导，避免抵消动作梯度；`1e-6`仅防除零，是数值适配。它在Q小于1时也可能放大Q推动，因此并不保证每步都减弱Q。记录实际分母、缩放及触底次数。

## 实现与验证切口

- `fql.py`：旧配置默认mean、不归一化，旧函数结果保持；新增全局分母与min目标。
- `train_fql.py`：两项配置开关；导出Q附带版本设置；梯度诊断读的是**实际归一化后**的Q推动。归一化版限定无梯度累积，避免将微批分母误称整个更新的分母。
- `fql_v2_plan.py`：复用旧200轮评估生成器，但明确恢复实际warmup55，独立版本、最新完整点保存。
- `fql_fix_smoke.py`：仅参数化版本名，复用12→14续训、原生N1导出、两卡各32回合Q诊断链。
- 正式复用 `single_formal_queue.py`，既有回放复用、错误留档/精确清场、失败推进RLT机制；不另写训练调度器。

CPU验证15项通过，包括手算min目标/终止、归一化顺序与停止梯度、零分母、两进程Gloo合批一致性、旧默认、转移边界、Q真实回报和200轮预算。短测采用1机2/3物理卡；正式从原始基座新训，不接着14步smoke续训。

评估继续保存未归一化的Q1/Q2和真实折扣回报，防止只看到缩放后数值正常。两项改动只能检验是否改善高估与策略退化，不能预先保证Q准确或成功率提升。
