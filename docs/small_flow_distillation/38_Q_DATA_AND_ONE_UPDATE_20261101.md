# Q到底用什么数据、怎样学习

2026-11-01。代码与现有产物复核；本轮没有启动新的FQL训练或采集。

## 先理解Q的工作

Q是一个“预估成绩”的小网络。输入当前画面、机器人状态、候选动作块、剩余步数，输出：先做这个动作块，后面继续由当前学生执行，预计还能获得多少奖励。它不是成功标签，也不是对动作正确性的人工评分。

我们一局最多成功一次、给1分，折扣后的真实回报在0–1。Q输出却没有被强制限制在0–1，所以它可以算出12；这说明评分失准，而不是机器人获得了12次成功。

|FQL评估记录|当时学生实际执行时，每块的Q、奖励、结束位置和最终成绩|能倒算实际回报、检查评分；没有完整前后观察与动作，不能直接作为新训练回放|
|新N1/N5/N10信号采集|Sidney多任务N10实际执行，41任务1312局；N1/N5只旁算；有原始动作、内部路径、观察、帧映射和视频|用于信号画图与对比；没有N1动作实际执行后的新场景和奖励，也不是当前单任务模型的回放|

这里的一条“转移”是一个动作块前后的变化，并非每个仿真物理步。把N1旁算动作配上N10执行后的画面，会制造错误的动作—结果对应，不能这样训练Q。

## 现有FQL每次更新做什么

1. 从固定405条回放中随机抽一批。取到“旧场景、老师当时实际做的动作、眼前奖励、执行后的场景”。训练期间不新运行机器人。
2. 在执行后的场景，让**当前N1学生**提出下一块动作；让缓慢更新的Q副本估计它值多少。这里没有真实执行学生动作。
3. 给当前Q构造答案：`眼前真实奖励 + 0.99 × 预计的以后奖励`；已经结束的回合不再加未来项。当前Q学习给记录中的老师动作打出这个分数。
4. 在旧场景，同一噪声下让固定N5老师与N1学生各提动作。学生同时接受两种要求：`30 × 与老师的动作误差 − Q评分`。既尽量贴近老师，又尝试让Q评分更高。
5. 两份梯度均在本次参数更新前计算，学生与Q各更新一次，再慢慢更新Q副本。下一轮换一批旧记录和噪声，重复。

代码位置：[训练循环](../../tools/pi05_distillation/train_fql.py)、[损失定义](../../rlinf/algorithms/pi05_distillation/fql.py)。老师与视觉语言部分冻结，学生动作专家与Q学习；两路Q取均值，与当前官方默认配置一致。当前55步warmup仅为学生学习率预热，没有独立的Q预热阶段。

## 为什么loss小，Q却可以越来越错

假设一条成功轨迹最后三块的奖励为0、0、1。按真实结局倒算，这三块的实际回报是0.9801、0.99、1。

但现有训练并不是直接拿这三个数当答案。它在下一场景询问学生的新动作，再用Q估计其未来价值。如果Q误报12，前一块的训练答案就变成11.88。当前Q学到11.88，loss会很小；机器人真实成绩依然最多1分。

这条链同时包含“固定旧数据”“对未真正执行的学生动作估分”“用估分再制造训练答案”。原FQL也有这类离线RL高估风险；不是我们的代码专有现象。当前检查未发现重复奖励或终止处理错误，但这不能证明整个适配无问题。我们只有128局、13局失败，且已有能力的学生立刻接受新Q指导，数据覆盖、评分可靠性和指导力度需要专门验证。

末代实测：Q训练loss约0.0024，学生真实执行时平均Q为12.27、实际折扣回报0.84；因此大谷不能简单解释为“Q还没收敛”，后段回升也不能证明Q学准了。详见[完整谷底审阅](36_FQL_FIX_VALLEY_AUDIT_20261101.md)。

## 最小修复思路与需要的数据

- **先让学生保持原样**，Q先学，暂时不推动学生改动作。这样先保护原N1能力。
- **给Q真实标尺**：复用现成FQL采集器，把执行策略改成固定N1学生，保存完整前后观察、动作、奖励与终止；用整条轨迹的实际结局倒算回报。按整局/种子分训练与验证，不能把同局相邻动作混入两边。旧N5老师回放可以辅助初始化，但后续策略不同，不能当成N1的真实答案。
- **通过验证再逐渐启用Q**：看留出回报误差、越界比例、评分分箱和成功/失败排序；保留老师约束，缓慢增加Q影响。学生改变后Q仍持续学习、继续检查。

先训Q能够减少“未经训练的评分立即改变好策略”的风险，不能保证消除数据覆盖不足。只增加warmup次数、只看loss都不够。alpha从10改30已经实施并完成；上述Q预热与新N1回放仍是下一轮候选，尚未启动。

## 原FQL为什么不用单独预热

官方流程将行为流模型、一步学生和Q联合训练；行为流本身也用离线数据学习。我们则从有能力的预训练π0.5开始，冻结多步老师，只训练一步学生和Q。初始化方式、网络/动作尺度、任务数据覆盖都有变化，不能要求原超参数直接适合。官方明确要求按环境调alpha；论文平均成绩也不等于保证每一轮Q都可信、所有设置都无谷底。

依据：[官方算法与调参说明](https://seohong.me/projects/fql/)、[固定版本官方更新代码](https://github.com/seohongpark/fql/blob/e8cd16eb490332924dfa2492097219f181765933/agents/fql.py)、[离线RL外推误差](https://proceedings.mlr.press/v97/fujimoto19a.html)。原FQL机制来自论文/源码；预热、真实回报验证和渐进启用是针对当前π0.5适配与实测失准的修复建议。
