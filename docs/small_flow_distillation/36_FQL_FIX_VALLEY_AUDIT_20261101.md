# FQL-fix：大谷、后期恢复与持续Q失准

2026-11-01。只读核对已完成单任务FQL-fix的27次完整评估、两rank训练指标、108批Q逐块记录、405条真实转移及训练/评估源码。本轮不改训练、不占额外GPU；图表在服务器CPU生成。

## 结论先行

谷底是实际策略退化：160预算轮20/128=15.625%，末代400轮113/128=88.281%。27次都为相同128个实际种子、相同生成噪声/执行协议，全部完整；训练种子与评估无交集。没有缺测分母、混入N5、切换C50/200上限来解释这条谷。

后期恢复与学生学习率减小、师生动作误差下降同时发生；Q绝对评分却继续恶化。因此“Q经过谷底终于学准”被现有记录否定；“更新逐渐收小、模仿约束重新稳住策略”是当前更相容的解释，但不是已完成因果对照。

## Q究竟有什么问题

Q要预测“执行该动作块后，继续跟随当前学生，未来还能得多少折扣奖励”。每局首次成功只奖励一次1，预算终止后不再累计；真实值应在0–1。

末代真实执行402条记录：Q均值12.275、实际回报0.842，平均绝对误差11.433；100%评分越过0–1。两个Q平均只差0.140，它们可以一起错；简单把当前双Q改取小值不会立刻把12变成1。初始状态的成功/失败排序AUC约0.564（0.5为随机排序），该指标只反映跨场景区分，不等价于同场景选择更好动作的能力。末代只有15次失败，排序估计还有统计波动。

训练的Q损失却降到0.0024，因为它在拟合自己构造的目标。例：下一动作错误地估12，当前奖励0，目标就变成0.99×12=11.88。当前Q接近11.88时loss可以很小，即使真正会失败。这是“自己的错误预测变成下一次答案”的反馈。

源码中的当前Q、目标Q、学生动作均无回报范围限制；对数据外动作的高估会被学生追逐，又进入下一状态的Q目标。该机制符合离线RL的外推风险，但现有日志不能唯一证明每个动作梯度都因这个机制而错误。[BCQ论文](https://proceedings.mlr.press/v97/fujimoto19a.html)、[CQL](https://arxiv.org/abs/2006.04779)

## 明确的适配风险与排除项

- 实际反馈只有128条老师轨迹、405条转移：115成功、13失败。Q约447万参数，动作输入C50×14=700维；固定数据覆盖很窄。全局batch448，4400更新共约197万次抽样，平均每条转移被取约4867次。“400预算轮”是与示范窗口训练量对齐，不能误解为小回放池只遍历400次。生成噪声是新的，真实执行反馈没有增加。
- 学生已有N1成功率76.6%的能力，Q随机初始化就参与指导。首批Q/已乘alpha的模仿动作梯度比仍6.30；alpha10旧版约18.9，alpha30减弱了但没有隔离随机Q。谷底阶段这个比值通常已接近1，不能只用“比值小于1”判断方向正确。
- 学生最高2.5e-5、55更新学习率预热、单次4400更新余弦衰减；Q固定3e-4且每次都更新。没有200轮重启学习率，没有单独Q预热。220–300轮附近记录中约85%的学生梯度被clip1裁剪；说明拉扯强，不能直接据此归因于梯度爆炸。全程记录未见非有限值。
- 检查405条奖励/终止记录：成功共115次奖励、128个终止，只有末条停止bootstrap，未发现重复奖励/终止仍续算。训练恢复代码加载学生、Q、目标Q、两个优化器和RNG；配置不一致会拒绝，不是每次评估后重置Q。
- 配置写有flow_sde，但eval分支实际固定选择flow_ode；不能据此误判训练/评估积分不一致。Q特征训练与评估共用pooled_features，Q导出步数与学生一致，诊断开关的动作/RNG对照通过。
- 原FQL对动作剪到[-1,1]；此处保持原生pi05归一化，真实数据4.75%坐标越过这个区间，范围约[-1.27,1.27]。不能直接照抄剪裁，否则会改掉合法动作。末代学生动作超范围的具体分布本轮没有重新跑GPU测量。

这些检查支持“算法/适配稳定性问题”，未定位到奖励公式或恢复某一行写错；不表示所有实现错误都已排除。

## Warmup有没有必要，怎么收敛修复

原FQL没有单独Q预热：行为流、一步学生、Q从头联合学习。其默认Q均值聚合、固定Adam 3e-4；提供min聚合及Q项归一化选项。我们的强预训练学生、冻结老师、极小回放池与原基准不同，因此预热值得做，但不是补上原论文必需步骤。[固定版本源码](https://github.com/seohongpark/fql/blob/e8cd16eb490332924dfa2492097219f181765933/agents/fql.py)

建议下一轮分两层处理，保留当前成功末代与整条曲线：

1. **保护已有策略**：先固定学生，检查Q的真实回报标尺，再渐进启用Q指导。若用现有完整轨迹的Monte Carlo回报预训练，它估的是采集老师的行为价值，只能作初始化；验证学生Q仍要用学生自己的留出执行。不要只看预热loss下降或机械多跑几百步。
2. **控制后续高估**：最小对照可把alpha30→100（Q相对模仿影响再降为0.3倍），并测试官方min/normalize选项。已知0–1真实回报可作为目标截断/有界Q的工程对照，但它会改变原FQL，且“数值在范围内”不等于排序正确。保留真实回报MAE、越界比例、初始状态排序；Q仍失准时不继续放任它强推学生。

单纯降低Q学习率或多做预热只能改变速度，不解决“未见过的学生动作缺少真实答案”。更根本的是增加偏离老师时的成功/失败覆盖；当前仅13条失败轨迹是明显不足。CQL/Cal-QL提供保守性与校准思路，但比本轮最小修复改动大，先保留为后续候选。[Cal-QL](https://arxiv.org/abs/2303.05479)

本轮没有重开修复训练；先明确小回放、高估反馈、学生步长三者的证据，避免同时改一大组参数后无法解释。
