# 从一条机器人记录理解：原FQL与我们的差别

2026-11-01。回应“不要默认我懂组件；老师采、学生学究竟与原版哪里不同”。先解释事实，再命名组件；不将可能机制写成已经验证的原因。

## 先看记录里究竟有什么

机器人实际抓一次瓶子，可以记录：抓之前的画面和手臂位置、这一段做的动作、抓之后的画面、是否已经完成任务。未完成给0，首次完成给1。完整一局把这些记录串起来。

“策略”就是看画面和状态、决定动作的模型。“老师/学生”在这里指算5步/算1步的两个动作模型，不是人。“Q”是另一个小模型：给它画面、状态和一份候选动作，让它预测接下来能得多少分。它的预测与真实奖励不是同一件事。

## 原FQL怎样用这些记录

采集者先留下固定记录，可以是旧策略或人；训练出来的学生不必是采集者。随后同时学习：多步动作模型模仿记录中的行为；评分模型学习评价动作；一步动作模型既模仿多步模型，也尝试获得更高评分。训练时主要反复读旧记录，并没有为每一个新学生动作重新运行机器人。

一条记录确证“动作a带到了画面B”。现在想知道从B开始交给新学生还能怎样，于是让学生在B提出下一动作，用评分模型估计后续成绩，再将估值加到已经真实得到的奖励上。这种构造答案方式是原FQL自带的，并非我们的特殊处理。记录中的a与B没有被替换或错配。

## 实质差异及可能影响

|环节|原FQL|我们|与当前问题的联系|
|---|---|---|---|
|谁收训练数据|使用基准的既有记录，非要求新学生自采|固定N5 π0.5执行128局|“其他策略采集”这一性质相同，本身不是违规数据用法|
|有多少真实经验|OGBench/D4RL各任务各自的数据集，覆盖与规模不同|仅405条C50动作块转移，115成功局、13失败局|新动作未被记录覆盖的风险明显；不凭这些数量断定唯一原因|
|多步老师怎样获得|在该数据上同时学习行为模型|用已经可用的π0.5并冻结|约束目标固定；数据本来由它采，不能直接断言冻结造成不匹配或高估|
|学生最初怎样|官方新建并训练一步网络|从已有能力的π0.5初始化，原N1成功98/128|Q尚不准确就指导已有策略，可能破坏原本会做的动作；原版也有随机Q，并非其绝无风险|
|Q看什么动作/画面|环境动作向量；视觉任务另学图像表示|50×14=700个动作坐标，加冻结视觉语言特征、状态和剩余预算|表示与动作组合都改变了，不能把原Q参数当已验证适配；需实测其学习/泛化能力|
|学习答案怎么来|真实即时奖励＋下一学生动作的估分|相同结构|估分变成答案是共同机制；错误可能经此传播|

因此应问“这些真实记录是否足以约束新学生可能提出的动作，以及评分是否准确”，而不是只问“是否学生自己采的”。把采集者改成学生会提供更贴近它的反馈，有利于诊断；有限数据仍可能遗漏其他动作，学生一更新又会变化，不保证从此无误差。

## 与12分的证据关系

末批Q训练答案平均8.599、预测8.601，说明高估已进入目标；完整执行时平均Q12.27、实际0.84，说明偏离真实成绩。405条固定记录没有随训练变多，这使“新动作估错→学生追高分→高分进入新答案”成为合理解释。

本次没有发现奖励重复累计或动作/后果错配；没有做增加覆盖、冻结老师开关、输入表示等隔离对照，所以不能声称已经定位唯一根因。老师被冻结不是已证明的错误。新任务归一化建议此前未落实、Q可信度未先验证充分，是应明确承认的适配不足。
