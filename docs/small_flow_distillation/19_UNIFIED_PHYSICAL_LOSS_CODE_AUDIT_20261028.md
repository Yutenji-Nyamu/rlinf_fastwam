# 五种蒸馏统一真实动作评分：代码审计

2026-10-28。审阅基线`1dc6e6b38`，本轮仅讨论和规划，未改算法、配置生成器、正式配置或队列，也未启动测试。既有源码/轻量回执用于定位，不代表重新刷新服务器。

## 本次讨论的统一规则

**模型继续处理H50×32，只在动作损失中评分真实14维，并按有效元素数量平均。** 适用于单任务原生RLinf π0.5和Sidney多任务π0.5的新实验版本；不变更已下载老师，不改原生SFT实现。建议采用此统一口径以减少跨方法的评分范围差异，不宣称原来的全维方案是确定错误。

- 真实14维包含双臂关节及两个夹爪；夹爪不做delta变换不代表它无效。
- 当前所有RoboTwin任务都使用这14维。`model.openpi.action_env_dim=14`是物理维数；加载后的内部`teacher.model.config.action_dim`可能是32，不可取错。
- H50是预测长度；C10/C50是执行长度。后40个预测动作不是维度padding，本轮不裁时间轴。
- `DemoWindows`只抽完整H50窗口，不跨回合、不补末尾时间帧；本次不需要新增回合末尾mask或改数据池。
- FQL的实际执行长度mask另有用途，继续保留。Q损失是评分误差标量，不存在裁成14维的问题。

## “只改算分”与“只生成14维”有区别

输出层和输入层继续32维，权重形状、归一化和加噪接口不用改，原始权重可以继续加载。被排除的只是损失里的直接评分项。

模型内部共享特征仍允许空位影响真实输出。CP尤其需要保留这一事实：最后只比较14维，也可能经EMA收尾的输入导数，让中间的其他坐标得到间接梯度。**不能把“所有中间padding梯度必须为零”写成验收条件。**

DMD在同一个含噪位置比较老师和辅助，选14维的指导是完整模型指导的投影。辅助只拟合真实分量是可实现的新目标，但不因此自动成为严格14维边缘分布模型。

MFD还会让辅助沿自己的速度场连续走若干步。即使最后只比14维，未直接监督的18维轨迹也可能通过模型输入影响下一步真实速度。因此“全分支14维”需要短测这一现象，不能只验证loss变小。若确实不稳定，应先明确讨论是否保留辅助全维约束；不能悄悄改成逐步清零空位、复制老师空位或改噪声路径，这些都是额外方法改动。

## 归一化与方法目标仍分别处理

普通MSE的旧值为`(14*真实误差+18*填充误差)/32`；新值为`真实误差`。不能把18维误差设零后仍除32。逐个真实坐标的系数由`1/32`变成`1/14`，不代表总梯度固定放大32/14，因为同时去掉了填充项，并有优化器与裁剪。

CP现有距离采用其参考代码的特殊平滑形式；本次不换距离公式。若参与评分的维数改为H50×14，沿原维度规则得到delta约0.01429（旧约0.0216），应明确记录。这个变化会影响小误差区的梯度，不能只比较新旧loss绝对值。

DMD辅助保持epsilon目标，MFD辅助保持velocity目标；二者不因“统一14维”而改成同一种损失。学习率、5:1、EMA、时间分布、老师步数各保留当前方法依据。

## 其他需要同步的轻量记录

- DMD/MFD可继续记录`fake_padding_mse`用于诊断，但标明不参与新目标；日志中的`fake`要注明新版本评分范围。
- FQL当前输出梯度RMS包含18维零梯度，数值是有效14维RMS的`sqrt(14/32)≈0.661`。两项使用同一分母时比值不受此因素影响；单列真实维RMS可避免误读，不改Q或actor目标。
