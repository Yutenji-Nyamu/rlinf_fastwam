# 统一真实动作评分：最小实施计划，尚未下发

2026-10-28。用户本轮要求全面审阅切口、维护上下文、继续讨论。源码审计见[19](19_UNIFIED_PHYSICAL_LOSS_CODE_AUDIT_20261028.md)。以下仅是实施方案，不是已授权启动新的实验。

## 建议采用的统一约定

对新版本五种方法：**所有按动作坐标计算的学生/辅助损失均仅评分真实14维，按有效元素平均；内部H50×32模型保持。** 单任务和多任务采用同一规则。Q的标量目标保持方法原定义；不把预测后40步当作padding。

这是减少比较口径差异的合理选择，不是“主流统一规范”。DMD/MFD辅助拟合目标也随之变化，MFD的内部积分影响须短测；理论和工程边界见19。

## 最小代码范围

|文件|计划改动|保持的部分|
|---|---|---|
|`losses.py`|复用一个轻量真实坐标切片函数；CP两项/DMD辅助接可选评分范围|时间采样、目标公式、老师/EMA梯度归属|
|`mfd.py`|辅助MSE真正裁14；学生继续14；诊断注明范围|两路完整积分、Euler步长、batch合算与无梯度路径|
|`fql.py`|端点锚定接统一维数参数，默认14以兼容旧行为|Q标量目标、输入C×14和实际执行mask|
|`train.py`|在入口一次解析统一规则，传给全部分支；resolved明确学生/辅助各实际范围|模型构造、供数、冻结前缀、优化器、保存与导出|
|`train_fql.py`|接统一维数；有效动作输出梯度RMS明确按14维统计|Q更新顺序、转移数据、归一化、奖励|
|`single_task_prepare.py`、`prepare_mfd.py`等实际配置生成器|为新实验显式写统一规则；保留旧配置复现路径|现有任务、batch、评估、卡队列和资源安排|
|现有测试文件|覆盖新模式，保留旧模式检查|不新增大型通用mask框架|

不需要编辑OpenPI/Gemma共享安装包、压缩输出层、重训老师或重新采集数据。只做坐标选择不会明显节省模型前向计算，也不自动带来成功率提升。

## 配置和旧实验兼容

建议新实验只增一个明确字段，例如`loss_coordinate_scope: physical`；真实维数取已有`model.openpi.action_env_dim`，本平台固定核对为14。

- 开启统一规则时，CP两项、DMD/MFD学生与辅助、Direct/FQL端点全部解析为14；不能只改学生字段然后称“全方法统一”。
- 历史`loss_action_dim`、`onedp_loss_action_dim`、`mfd_loss_action_dim`作为旧配置来源保留；新规则下发现矛盾值则在启动前指出，不静默覆盖。
- 未声明新规则的旧实验继续保持旧默认与显式配置。DMD/MFD旧辅助仍全维，CP旧两项仍全维；当前续训队列保持原定义。
- 记录实际resolved范围，不仅记录用户传入字段。新的辅助loss含义变化时，图表不能直接与旧全维loss串成一条同定义曲线。
- 权重结构兼容不等于训练目标未变。若未来比较新版，从同一原始老师初始化最清楚；若用户选择从旧点继续，应另命名分支阶段并注明目标切换。原完整续训校验不放宽。

本方案统一的是坐标评分范围，**不统一不同方法的学习率、损失类型、更新比例、模型附加组件或预算**；这些继续按各方法既有依据。

## 少量必要验证，未来获准实施后执行

1. **输出评分检查**：仅改变最终待评分张量的18维，loss应不变；改变真实14维应生效；MSE分母按`B×H×14`。不要把这个检查错误扩大为“任何含噪输入的填充改变都不能影响网络输出”。
2. **梯度归属**：Direct/DMD/MFD最终生成动作的被排除分量无直接目标梯度；CP仍保留经EMA收尾向学生传递的完整输入导数；辅助更新不能改学生，老师保持冻结。
3. **CP距离检查**：选定14维后按既定公式算delta和距离，保留数值稳定写法；同时检查旧模式保持原输出。
4. **调用与恢复检查**：实际训练入口传到辅助，而非只改变日志；新配置完整保存、同配置恢复通过；旧点改范围不能冒充同实验恢复。现有覆盖优先复用。
5. **短GPU检查**：沿已验收的各方法batch，只做少量更新/续训/实际N1导出；对CP及两个辅助观察真实维误差、梯度范数、裁剪频率和耗时。新范围改变梯度尺度，先测，不按32/14机械调整学习率。
6. **MFD额外检查**：在少量已有积分中记录真实/填充位置和速度的量级，查看是否漂移；用同一小批比较辅助真实维拟合及最终指导是否有限、稳定。有限值只能验工程可用，长期成功率仍需正式对照。若短测出现实质漂移，再讨论方案，不自行改积分路径。

以上是计划，没有在本轮执行项目测试或占用GPU。未来检查在服务器按当轮卡授权进行。

## 与CP dropout分开

本轮统一评分先独立定义；dropout仍见[18](18_CP_DROPOUT_WALKTHROUGH_20261028.md)，暂不混入此版本。这样未来观察到变化时，更容易区分评分范围与网络扰动各自的作用。不自动追加实验矩阵或更改队列。

讨论结论：优先保留“全方法动作损失真实14维”作为新版统一方案；先完成上述必要验证，再决定是否正式替换。当前仅文档规划。
