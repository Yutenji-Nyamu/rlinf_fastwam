后续执行以[42实施记录](42_FQL_V2_IMPLEMENTATION_20261101.md)为准：用户新授权正式200预算轮、2200更新、17次评估；下面400轮建议属于更早讨论，已被本轮预算替代。

2026-11-01。用户确定名称FQL v2、启用两项官方机制，要求先规划。本轮只查代码、配置与已有证据、维护文档；未修改训练源码、占卡、smoke或加入队列。

## 版本边界

从已完成的单任务FQL-fix实配复制，使用同一原生RLinf adjust_bottle π0.5、N5老师、N1学生、H50/C50、200动作上限、同一128局/405条真实转移和同一评估种子。老师及视觉语言部分仍冻结。新实验从原始预训练学生和新初始化Q开始，不从已经严重高估的FQL-fix末代续训。

|设置|FQL-fix|FQL v2规划|依据|
|---|---|---|---|
|Q训练答案的双头聚合|mean|min|官方q_agg选项|
|学生目标中Q项的尺度|原值|除以该批平均绝对Q|官方normalize_q_loss选项|
|学生目标中双Q聚合|mean|仍mean|官方源码；不要将target的min误用到所有位置|
|alpha|30|首版对照先保持30|用户本次仅改两项；不暗加第三项调参|
|Q诊断|开启|保留原始Q与真实回报|旧FQL-fix已验收|
|Q预热、新回放、动作/回报截断|无|本版不附加|这些尚是另外的讨论项|

归一化会改变实际Q/模仿力度，即使alpha仍为30也不等价于旧版。先用30可回答“原实配加两开关怎样”；它不是已经调好的最优值。官方建议归一化后另调alpha；若后续要优化参数，将10等候选单独标成参数对照，不通过14步smoke成绩选最优，不悄悄改正式配置。

## 精确计算

Q训练答案：

`target = reward + 0.99 * bootstrap_mask * min(target_q1, target_q2)`

学生目标：

```
q_sample = (q1 + q2) / 2
denom = mean_over_batch(abs(q_sample))
scale = 1 / stop_gradient(max(denom, 1e-6))
loss = alpha * endpoint_mse_14d - scale * mean(q_sample)
```

注意是“先每样本两头取均值，再绝对值，再跨样本平均”；不是abs(mean(q))，也不是直接对两个头分别取绝对值后平均。scale须脱离梯度，否则会改变官方更新方向。Q值很小时，归一化也可能放大指导，不能把它解释成永远降低Q权重。

1e-6仅作浮点分母零值保护，是明确的工程适配，不是论文超参数；原官方代码未加此下限。记录触发次数，正常分母下公式一致。若实际频繁触发，停止把短测判为通过并查初始评分，不能追加一个未经讨论的放大倍数上限掩盖它。

## 修改切口

|文件/入口|计划改动|复用边界|
|---|---|---|
|`rlinf/algorithms/pi05_distillation/fql.py`|bellman_target增加默认mean的聚合选项；actor_objective接收脱离梯度的缩放系数|TwinQ结构、旧调用默认行为不变|
|`tools/pi05_distillation/train_fql.py`|读两个开关；在已有Q前向后计算全局分母；传入两处损失；记录原始/实际Q项和scale|老师/学生前向、优化器、目标Q更新顺序、回放不变|
|现有FQL-fix配置准备路径|内部method仍fql_fixed_teacher，experiment_name=fql-v2，独立输出/部署|推理加载器无需新增模型类型|
|`fql_fix_smoke.py`|只将标签/输出及配置断言参数化，v2入口复用相同12→14和导出评估流程|不重写调度、超时或精确清场|
|`q_evaluation.py`及小Q导出元信息|保留q1/q2原始值；补记版本与聚合/归一化选项；min可由原记录离线算|实际回报对照仍用原始分数，不能拿归一化后的学生损失当校准结果|

**双卡细节：** 当前每卡224、总448，梯度累积为1。两卡将脱离梯度的abs(q)总和与样本数做一次小量归约，得到共同scale；不能各卡单独除以不同分母。无需额外模型前向。计算口径为global microbatch，当前等于整次更新batch；将来若改变梯度累积，要明确重新核对这一口径，不假装与整批448的公式自动等价。

**续训细节：** 现有恢复严格比较完整配置。旧配置不新增默认字段后再强行恢复，旧函数默认行为保持；v2将新增字段写入完整点，只有v2→v2原样续训。不得为从旧fix“续训成v2”去放宽这个检查。

## 参数与预算继承

实际FQL-fix已完成400预算轮对应4400次更新；这是与蒸馏示范窗口预算对齐，不是405条回放只重复400次。

- 训练：每卡224、总448；学生最高2.5e-5、55更新预热、余弦衰减；Q固定3e-4；双Q每头512×4、LayerNorm；目标更新系数0.005；随机种子721042。
- 建议未来正式预算同fix：400预算轮、4400更新；27次评估，每次128回合；原生每卡32环境×2批、无录像，保留Q诊断。此轮尚未授权执行该队列。
- 早期评估更新点保留14、28、55、110等，随后沿用已完成fix的全部27点。不要直接重跑旧formal_config生成器：它会按新总步数重算warmup到167，且旧fix helper只有200轮，会引入非方法变化。应复制已完成run的resolved实配，再显式改v2字段。
- 写盘按用户最新政策：新大产物Data，同实验仅最新完整续训点，日志/全部评估保留。旧fix实配里的latest2_best是历史政策，不能照搬成新v2存储策略；使用已验证checkpoint_keep_last=1、无固定保留步数，评估点单独登记，不改旧权重。
- 旧短测每卡峰值约72.9GiB张量、77.4GiB预留、8.7秒/更新，仅为历史参考；两项主要是小张量归约，不新增网络、数据或大保存文件。容量从已验证224直接开始，不从小batch逐级重测。

## 将来的最小验收

1. 无GPU：手算min与终止目标；缩放系数无梯度、零值有限；两分片分母与合批相符；默认旧调用输出/梯度不变。沿用现有测试，不重做整个采集链。
2. 有授权空卡后：12更新→完整续到14，原生N1双卡各32回合，复用旧短测。查损失/梯度有限、scale实际值、Q与模仿动作梯度、峰值/吞吐、恢复与导出对应。
3. 短测只证明程序能跑；判断效果仍需完整曲线。持续保留成功率、真实回报误差、越界比例、双Q差异、Q训练答案均值，避免仅凭loss下降宣布修好。

两项同时启用构成用户选择的v2组合，不能凭组合成功宣称各自贡献已经隔离。若仍有高估，数据覆盖、Q输入表示、合法动作范围、真实回报预热分别讨论，不临时堆进本版。
