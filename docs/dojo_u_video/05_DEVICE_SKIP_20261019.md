# Cleared device-fault continuation

The opt-in `skip_cleared_device_fault` lane setting allows a failed task to be skipped after the task writes its result and a positive clearance receipt, and the live GPU process query confirms the card is clear. The next task starts in fresh processes with its original sampling, model, and recording configuration.

Missing results, invalid recordings, or failed cleanup still stop the lane. A device fault remains unresolved until a subsequent task yields validated episodes. If the finite queue finishes with an unresolved device fault, its final state is `BLOCKED_DEVICE` and the RLT release receipt is withheld.

Seven CPU tests cover failure routing and complete queue execution, including device failure followed by success and an all-device-failure queue. Runtime paths, process identities, and collection logs are retained outside the public change.
