# Pi05 EndpointDistill 10→1 · RoboTwin50

2026-10-22，用户授权实施。直接复用已跑通的π0.5 CP/OneDP模型、数据、续训及评估链，增加独立`endpoint`分支。正式位置为深圳2机6/7，顺序为OneDP → 本实验 → 原逐卡RLT；现场回执见`queue.json`。

## 方法和依据

同一观察、同一初始高斯噪声，冻结老师用原生10步ODE生成动作，学生用一次动作专家调用生成动作；仅比较归一化后的H50×14真实动作维度MSE。内部32维仍完整推理，不监督填充维。冻结VLM和老师，只训练学生动作专家及原动作/时间投影；不加专家FM、EMA、辅助分布网络或CP目标时间投影。

参考[RL-100 flow分支](https://github.com/Lei-Kun/RL-100/blob/6b6afceb7eb12525398207b5d6e66908863dc385/RL-100/rl_100/policy/rl100_3d.py#L1213)的同噪声终点回归思想。π0.5速度输出、原生ODE时间网格、归一化空间、14维监督属于本实现的明确适配，不称为RL-100原样复现。[固定Sidney基座](https://huggingface.co/SidneyXie/pi05_robotwin/blob/e49e2ab/train_config.json)及现有CP实配提供模型、数据接口和优化器依据。

## 最终配置

| 项目 | 设置 |
|---|---|
| 数据 | TianxingChen官方Clean50×50任务，2500示范，427287窗口；先均衡抽任务再抽窗口 |
| 教师 / 学生 | 同一Sidney基座初始化，N10 / N1，H50/C50 |
| 训练batch | 每卡192，全局384，双卡DDP；FP32主权重、BF16计算 |
| 优化器 | AdamW，lr 2.5e-5，β=(0.9,0.95)，eps=1e-8，weight decay=1e-10，clip=1 |
| 时间表 | warmup167更新＋cosine；学习率不随batch自动放大 |
| 预算 | 50预算轮，1113更新/轮，共55650更新、21369600个训练窗口样本 |
| 保存 | 每634更新及每个评估点保存完整可恢复状态，另导出学生动作专家 |
| 学生评估点 | 556 / 1113 / 2226 / 5565 / 11130 / 22260 / 38955 / 55650 |
| 每次评估 | 50任务×16回合；每卡两个任务，共64环境；各任务官方动作上限 |
| 对照 | 复用正在生成的同配置原始N1/N10全任务基线；不重复跑同一批 |

增加训练batch是用户追加授权的容量选择。相对原每卡64方案，数据预算完全相同，更新次数降为三分之一；warmup和保存间隔按相近样本数折算。不同batch的优化行为并非严格相同，最终需比较闭环成绩。

## 实测与验收

3机2/3按顺序短测，前两次启动影响不计入吞吐；每档取第2至第6更新的时间差。

| 每卡 / 全局batch | 峰值已分配显存/卡 | 训练秒/更新 | 窗口样本/秒 |
|---|---:|---:|---:|
| 64 / 128 | 31.44 GiB | 2.745 | 46.63 |
| 128 / 256 | 47.99 GiB | 5.484 | 46.68 |
| **192 / 384** | **64.55 GiB** | **7.954** | **48.28** |

选择192，短测吞吐比64高约3.5%，峰值保留显存65.33 GiB。显存占用增加不等于同比提速；这些短测不证明训练质量。按短测折算纯更新约123小时，另加评估、保存、加载和排队，正式数据读取吞吐仍需首段校准。

原每卡64完成12→14完整续训和导出。每卡192完成6→14完整续训，保存的训练状态有效；最初把导出推理也误设为192时触发OOM，正式评估每任务实际为16，因此导出检查改为真实16批量。最终两rank推理回执见`smoke-selected.json`；只把完成验收的回执作为排队启动条件。

CPU共9项针对性测试通过，包括同噪声、老师停止梯度、填充维不参与损失、CP/endpoint导出接口区别，以及等待队列取消不能提前放行RLT。原生初始N1与可微学生表达式最大差异为0。评估入口依赖完整导入通过；部署包含已验收的`pi05_signals`和`pi05_u_video`工具。训练smoke不代表新方法已获得闭环成功率。

## 队列与恢复

控制目录：`/data/chenyiteng/deployment-20261022/endpoint-multitask-sz2-g67`；结果：`/data/chenyiteng/results/pi05-distill/endpoint-multitask-clean50-sz2-g67-20261022`。源码在控制目录的隔离`source/`，不改正在运行的CP/OneDP源码。

入口：`python source/tools/pi05_distillation/endpoint_queue.py <控制目录>`。实际命令、模型配置、资源和队列身份分别见`config.json`与`queue.json`。先等OneDP完整释放，再接6/7；训练停滞、异常退出保留错误，清理仅本事务的精确进程；评估异常批次留缺测并继续，正常未成功计失败。最后恢复逐卡RLT，完整CP250及新续训runtime均已登记。

本轮修正了一个交接缺陷：取消尚在等待的旧endpoint队列时，OneDP恰在换阶段空出GPU，旧逻辑错误写了释放回执，导致两路RLT提前进入。已精确停止这两路RLT并清理其独立Ray命名空间，OneDP进程未被停止。新队列只有实际接管GPU后才可释放给RLT；有对应回归测试。详情见`wait-repair.json`，不把这次维护取消计为科学实验失败。

公开文件仅源码、配置、短测、测试及调度回执。权重、优化器状态、原数据、回放、完整视频和凭据留在原存储；没有按“中间点”删除任何正式checkpoint。
