# BC 全量实验复盘与下一设置决策

2026-09-11。合并17条正式运行的冻结记录，重新计算11组方法配对及同采样预算；最新8/U5采用11:19 R100快照。本页是分析和候选方案，未启动BC、修改训练或删除文件。旧实验归档由本轮收尾账本另行记录。

**现有证据支持“方法效果依赖数据与更新的组合”，还不支持“baseline越弱，DVAC越有效”。目前没有一组已验证同时达到历史最强clean的绝对表现，并稳定超过它。** 更合理的目标是保留尚可的baseline，再让重加权补足可诊断的缺口；不必先把baseline调弱以得到正差值。

## 2. baseline 到底怎样变好：样本、更新和反馈分开

全部主要运行使用原始Sidney π0.5、空池、expert-only、LR2.5e-5 constant、Adam(0.9,0.95)、clip1、1024/micro32、M10/C50/D14及相同声明seed；更早8/U2/32/U10与后续代码版本不同。旧[0,2]和[0,5]并非只改上界：前者chunk均重1，后者允许整chunk降/升权。新1/1再改为完整训练batch的两级MinMax＋中心化。精确配置来源随数据集附存，不能把跨方法版本当单参数消融。

| 比较 | 严格共同窗口 | 固定评估结果 | 可以得出的结论 |
|---|---|---|---|
| clean 4/U5 → 8/U10 | **40–400次采集，共10点；两者U/N=1.25** | 43.44 → 61.56%，**10点全胜、+18.13pp** | 优势不只是8/U10最后多采了400条；同采样、同累计Adam仍更强 |
| clean 4/U5 → 4/U10 | R5–45，共9点 | 40.28 → 32.29%，**−7.99pp，0胜2平7负** | 小采集量下加倍更新没有恢复baseline；目前不优先继续加U |
| clean 8/U2 → 8/U10 | R5–75，共15点 | 58.13 → 63.13%，+5.00pp | U并非无影响；更多拟合有收益，但远小于5倍更新量 |
| clean 旧8/U10 → 新8/U5 | R5–100，共20点 | 65.63 → 58.59%，−7.03pp | 同时改了U、指令、过滤，**不能说减U导致全部下降** |

**N不是SGD batch。** 每次Adam仍有放回抽1024个成功query。N较小改变的是成功池新增量、策略更新前有多少独立成功、采集/更新交替频率；并没有把1024变成4。U/N相同也不能保证相同池、相同轨迹或同样泛化。4/U10的下降与小池高复用过拟合/早期分布锁定一致，但尚未证明具体根因。

小数据还应包含实际交互成本：历史4/U5的100轮是400次训练尝试，但每5轮fixed32额外640次评估；若讨论真机数据效率，应分报训练采集与评估成本。跨N的MA10分别覆盖40、80或320次采集；只把横轴乘N并不能得到同窗比较。[已有严格40/160次窗口](evidence/bc-budget-comparison-20260908/README.md)

## 3. 最新8/U5为什么还没拉开：数据链提供的线索

这一对已消除指令版本和长度过滤的组间差异，值得作为当前**尚可baseline**。全程fixed 58.59%、尾5 62.50%；它不是历史65.63%的同协议复现，但也不像旧4/U5那样明显偏弱。

| R100实际数据 | clean | DVAC new |
|---|---:|---:|
| 800次训练采集中的成功 | 547（68.38%） | 496（62.00%） |
| 入池成功episode / query | 507 / 1521 | 477 / 1431 |
| 成功但因长度拒收episode | 40 | 19 |
| fixed全程 / 尾5 | 58.59 / 62.50% | 59.38 / 63.13% |

DVAC采集成功少51条，入池少30条；固定评估却几乎相同。说明方法改变了在线数据分布，但**“能更有效利用少数据”尚不能仅由最终池更小推出**：两个池的质量和覆盖已不同，权重只是其中一个原因。少拒收长成功也不自动等于学得更好，需要同时看总成功量。

新权重确实有幅度：R100平均1、std0.284、范围约0.239–2.430；局部std0.234、外层std0.155。外层std从R1的0.450降到R100的0.155，不能继续用smoke早期数据声称外层在整个训练中占主导。R1两边实际只入池1条episode/3个query，却各做5次1024抽样更新；R10才81/84个query。**1024掩盖不了初期独立数据很少**，这比简单“更新太稳”更具体。

旧4/U5的权重确实更强，但口径要分开：旧日志统计**当轮新成功query的有效动作位置**，new日志统计**当次回放1024-query训练batch**，不能拿两个std直接当倍数关系。旧R94的新入池权重均值1.042、std0.824、最小0、最大5；R2–94中90轮有权重记录，逐轮std平均0.847。65/90个有记录轮次出现过0、47/90出现过5；这是“出现过端点的轮次占比”，**日志不足以还原零权/触顶动作占比**。旧mean不固定为1，也改变整段训练份额，故旧4/U5收益不能证明“把new的alpha增大就会恢复”。[旧权重逐轮重算](evidence/bc-comprehensive-20260911/old4_weight_round_statistics.csv)；口径代码为`OnlineBCDvac.annotate()`及actor收包后入池路径。

仍值得区分的三种机制：

1. **信号是否选对动作。** 高V是成功标签中较不确定的位置，未必是最值得多学的位置；终止chunk仍监督完整提交proposal，末端未逐位置执行验证的问题也继承clean。两层归一化控制幅度，不能自动解决信号语义。
2. **权重是否主要在挑阶段。** 外层跨完整batch比较mean(logV)，可能改变第一/二/三段的总份额。局部-only能直接检查这一层的净作用；当前std较小并不证明无影响，也不证明有害。
3. **是否重复使用过时的不确定性。** V在行为采集时计算并缓存，new训练时只重算相对W；它描述产生标签时的策略，不是当前模型。增加U会更频繁复用这一历史信号。可先用固定成功池检查V与当前FM误差的阶段内关联、同序号置乱，不必立即增加在线前向成本。

这些是待辨别的假设，现有工程核验未发现权重完全未接入、分母/microbatch或非有限数值错误；测试通过不等于重加权方向有利。[实际训练量CSV](evidence/bc-comprehensive-20260911/latest8u5_training.csv)

## 4. 最少实验的建议顺序

**建议不同时扫N、U、过滤、LR和两级幅度。先固定“新指令＋过滤≤3”的协议，以8/U5 clean作为强度尚可的参照。** 历史最佳8/U10保留为性能目标，不把旧环境结果当当前协议的必须达到值。

| 优先级 | 候选 | 回答什么；依据与限制 |
|---|---|---|
| 1：优先方法诊断 | **8/U5，new alpha_local=1、alpha_chunk=0**；同协议clean配对/后续独立seed复核 | 保留已完成且尚可的baseline预算，只去掉跨chunk总量调整。若收益改善，后续试0.5；若仍无效，不能继续只调幅度。当前outer并不异常大，故这是辨别实验，不是已证修复 |
| 2：若更关心低数据假设 | **4/U5，新环境、两边过滤≤3，clean vs new 1/1** | 补齐目前最关键缺口：历史new4正差能否在完全匹配clean和修复环境后复现。每组先共同400训练尝试、500更新；不能只把旧4/U5 clean复用为新协议基线 |
| 3：已有正差的保留线 | **4/U5，旧[0,5]原规则与同协议clean** | 旧方法有15胜2平1负的配对证据，值得保留；它与new机制不同，不能只借用旧名字。新环境下必须重新验证，不能宣称已有收益自动迁移 |
| 4：再考虑中间N | 6/U5，先clean和选定方法成对 | 位于4与8之间有工程直觉，**目前没有6条的数据证据**；且U/N变为0.833，不能称只调反馈频率。若要研究N而控制U/N，可另立4/U5、8/U10这类成比例预算，别与本候选混称 |

1与2按当前优先问题选其一即可，不建议全开：想保住baseline并补方法，先1；想验证低数据机制，先2。旧8/U2虽计算省，但fixed方法负差，暂不作为“已有效的sweet spot”；4/U10已显示不利趋势，32/U10耗交互多，也不优先。

**如果这次明确想试“尚可baseline＋已经work过的旧DVAC”，我会选新协议8/U5＋旧[0,5]，而非再回旧8/U10或直接猜6/U5。** 它保留当前8/U5的采集量、更新数、修复和过滤，单独换回旧映射；现有同协议clean和new可以提供筛选参照，正结果仍应配对补seed确认。选择依据是8/U5 clean已有58.59%的完整记录、旧DVAC在U5/N4有正配对、在U10/N8有负配对；**这些不能证明N8/U5必然正收益**。这是旧方法的新预算迁移试验，与上表new局部-only实验是两条备选路线，不能同时变成“旧映射＋新局部归一”后还说只改一项。

候选通过标准应事先写清：共同固定预算的整段与尾段都看、采集率单列，确认后用独立seed及未参与调参的场景检查。可以预设“clean全程约55%以上、方法整段至少+5pp”作为内部筛选目标，但这是未来目标，不是当前统计显著性结论；不要通过反复挑baseline终点满足门槛。

## 5. SARM、IQL、AttenA给DVAC的共同提醒

这三条都说明**删改成功监督本身就有代价**，理论上“有额外信号”不保证优于成功BC。SARM确有必要动作被预测为负进展并整段置零；IQL R11同时转全池及exp强权，初期critic只50次更新；AttenA FK偏向后段，首动作大量触底。这些是各自具体实现/适配和数据行为，不能统称“数据少”或“重加权无用”。

如果后续回到它们：SARM优先保留0.5基础监督；IQL actor保留成功池、QV用全池；AttenA检查chunk均重归一。三者均为已有证据支持的独立消融，不应和本轮DVAC预算搜索一起改。[SARM/IQL完整诊断](BC_SARM_IQL_DIAGNOSIS_20260910.md) · [AttenA复盘](BC_ATTENA_POSTMORTEM_20260909.md)
