# 执行与验收

1. 固定host-key、普通账户身份校验；刷新SZ1实配与SZ3卡位、进程UID/PID/start/boot、Ray namespace、完整checkpoint和磁盘。
2. 独立源码/分支/输出/namespace；只移植Norm生产器和必要元数据，保存相对SZ1实配逐叶差异，部署路径与卡位单列。
3. 在深圳服务器执行针对性CPU合约：Norm读点与聚合、主动作/RNG不变、成功筛选、回放与checkpoint兼容边界；通过后发布审过源码并核远端SHA。
4. 精确保留并暂停6/7旧RLT，记录恢复命令/完整CP/资源归属；验证目标卡C/G及namespace释放。开发至正式保持同一租用期。
5. 每组使用实际正式并行规模smoke，缩短串行轮数。核对有限且非零梯度、非平凡Norm权重、实际更新、保存/恢复、计算和渲染绑定。任一不通过则留在开发状态修复，不让RLT自动插队。
6. 正式BC300、DSRL200均从SFT/空池重启。开始后验收首轮/权重与资源，记录唯一owner及心跳。结束或明确终止后，精确清理本组namespace和已核身份，再续原RLT累计预算。

停止条件：源码/配置pin不符、身份或资源归属不明、越界C/G、非有限值、保存不完整、磁盘不足。不重启共享Ray，不处理其他用户，不扩大到0–5卡。实际入口、命令、输出及测试/发布回执在准备完成后补齐。
