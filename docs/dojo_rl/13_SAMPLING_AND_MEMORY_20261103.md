# 每轮采样与显存换速度是两个参数

用户纠正：DSRL/RLT算法层保持历史小批采样，不为提高显存占用把每轮改为32局。正式采用DSRL8局/轮；GPU7现有RLT本来就是8局/轮。

## 三个独立数量

1. **新采样量**：与环境实际交互。本次8条轨迹，每条最多700个动作；C50下每轮最多112条动作块转移。改变它会改变策略多久更新一次。
2. **训练batch**：从旧回放抽多少条一起算梯度。DSRL为256；不是256条新机器人轨迹。
3. **microbatch**：同一个batch分几次塞GPU。DSRL256一次算完；RLT512目前分两次256。减少拆分是更直接的显存换速度，global batch、优化器步数保持。

DSRL继续UTD20：每新增一条有效动作块转移安排20次小网络更新，整轮最多112×20=2240次。预热500条之前不更新；早成功会减少有效转移及更新数。不是“采8条只更新8次”。

## 历史依据

- 成功π0 Clean DSRL实配：4局/轮、global=micro256、warmup500、UTD20，200轮共800局。本轮800总量保留，用户偏好8局/轮，对应100轮。
- 2026-10-07 π0.5也实际跑过8局/轮，但同时改warmup2000并保持200轮，预算扩成1600局；**本轮没有把整套不同预算一起抄来**。
- [历史microbatch测试源码](https://github.com/Yutenji-Nyamu/rlinf_fastwam/blob/ff64209f8ee668b35837ae6469509b7f0257b89d/tools/dsrl_u_20261006/microbatch_benchmark.py)：固定global256，对64/128/256合批比较。actor梯度同输入/同噪声比较过，已有依据支持当前micro256；它不是扩大global batch的依据。
- GPU7运行配置现场为训练8局、global512/micro256、验证4×5局。维持该正常候补，不改成32新采样。

## 本轮实施

- 32环境短测证明接入可走采样、更新与保存；不启动32环境正式训练。
- 8环境再做一轮已有点恢复，关闭actor/rollout offload，测试模型常驻显存。数据量、global batch、UTD不因该开关改变。
- 保留每次32局评估：8环境×4个不同固定布局批，加入小型轮换逻辑，两个评估循环均覆盖0–31的CPU测试通过。
- 正式每4轮保存一次最新完整点（仍每32局一次），评估0/12/24/36/48/60/72/84/96/100轮。
- 32环境首段计时：reset约259秒、100动作交互约255秒、模型推理约8秒、64次SAC训练约13秒。模型搬运可省部分时间；不能凭显存占用断言整体变快，更不能承诺单纯放大环境能提速。

低显存若来自冻结VLA、只训练小网络，本身正常。选配置依据有效吞吐、稳定性和算法合同，不能以占满六七十GiB作为唯一目标。

## RLT合批短测

复用7卡当前 `RLTMLPPolicy` 和实际维度：z2048、状态14、C10、FP32、global512。只创建独立小网络，未载入/修改正在训练的模型；输入固定合成数据。比较actor/Q前后向，未计完整TD、优化器、FSDP及仿真。

| 拆分 | 中位耗时 | 小网络张量峰值 |
|---|---:|---:|
| 2×256 | 6.13 ms | 105.6 MiB |
| 1×512 | 3.08 ms | 117.4 MiB |

512是有依据的后续合批候选，但这不是整轮提速一倍。RLT当前一轮约200秒、约160个更新，仅该测量部分折算节省约0.49秒/轮，不能凭它承诺大幅节省训练时间。正式RLT本轮继续既有8局/轮、micro256，避免为很小且未验证的全程收益中断健康候补。

用户最终决定保持当前配置顺利训练。DSRL已global=micro256；继续提高micro需要同时改global batch，改变训练设置，不能保证墙钟时间下降。8环境短测为UTD1，正式UTD20，短测的6.32秒更新不能当正式每轮训练时间；正式时继续依靠已有分项计时，不增加新扫描。
