# DSRL不提升：实现、数据与外部证据交叉核查

2026-11-05。范围：1机4/7 RoboTwin turn_switch、5/6 Dojo扔瓶子，Clean/+U四组独立噪声DSRL。仅只读采集与一次性CPU诊断；没有改变正式配置、权重、队列或GPU占用。

**当前最优先的具体问题是小型SAC网络的更新精度。独立噪声更难学也有论文及复现依据，但不能把当前停滞全部解释成“再等久一点”。**

## 1. 成绩没有形成稳定上升

15:22快照；末次评估不是训练当前轮。

| 组 | 已完成训练轮 | 起点评估 | 历史最高单点 | 最近完整评估 |
|---|---:|---:|---:|---:|
| RT2 Clean | 214 | 41.7% | 66.7%（117轮） | 33.3%（208轮） |
| RT2 +U | 185 | 33.3% | 58.3%（130轮） | 33.3%（182轮） |
| Dojo Clean | 81 | 62.5% | 78.1%（48轮） | 65.6%（72轮） |
| Dojo +U | 54 | 62.5% | 71.9%（24轮） | 62.5%（48轮） |

RT2每点评12局，成功一局就跳8.33个百分点；Dojo32局，一局3.125个百分点。峰值还不能当成稳定改进。训练采样的首20轮/最近20轮均值分别为：RT2 Clean 46.9%/33.8%、RT2 U 41.9%/38.1%、Dojo Clean 61.3%/57.5%、Dojo U 58.1%/58.8%。前段含随机噪声预热，描述趋势，不是配对显著性检验。

网页分别画独立评估与20轮滑动平均采样率；不把二者混成一条曲线。RT2 Clean续训产生重复TensorBoard step，按较晚wall_time去重。

## 2. 先理解每一轮学什么

π0.5权重固定。小噪声策略根据画面和机器人状态，选择50×32个噪声数；π0.5把这些数变成动作，机器人执行一块。保存“当前观察、这份噪声、执行后观察、奖励、是否结束”。Q网络学习评价这份噪声，噪声策略朝Q认为更好的方向改。

每轮8局；每增加一条动作块转移，按UTD=20安排20次小网络更新，每次随机抽256条旧/新转移。**200训练轮不等于200次参数更新。**

| 检查点 | 累计有效动作块转移 | 已执行小网络更新 |
|---|---:|---:|
| RT2 Clean CP208 | 13,199 | 224,060 |
| RT2 U CP182 | 11,448 | 189,860 |
| Dojo Clean CP80 | 7,444 | 140,180 |
| Dojo U CP52 | 4,885 | 88,280 |

延长400轮会继续增加真实经验；单纯调大UTD只会更多次重学已有数据。当前不能优先归因为更新次数太少。

## 3. 最直接的异常：小网络/Adam都存BF16

现场源码`openpi_action_model.py`把噪声网络、两套图像/状态编码器、Q头直接转换为BF16，理由是与大模型及FSDP保持dtype一致。保存点确认其权重和Adam一、二阶状态均为BF16；未见在线参数的FP32主副本。目标Q虽然有FP32 EMA影子，它只修目标网络的平滑更新，不能替代在线网络的高精度参数/优化器。

通俗地说：网络算出一个小改动，但存数的刻度太粗，加完又被四舍五入成旧数。重复训练不等于这些小改动会自动累积。

做了一次受控CPU对照：读取真实Clean检查点和64条真实回放，算一批Q梯度；两边使用同一份已量化梯度、相同Adam历史和学习率，仅改变参数/Adam存储精度，更新后全部丢弃。**没有用GPU，也没有写回训练。**

| Q头中有非零梯度的参数，本次更新后数值仍不变的比例 | BF16 | FP32 |
|---|---:|---:|
| RT2 CP208 | 99.55% | 0.015% |
| Dojo CP80 | 99.27% | 0.017% |

图像编码器也出现大量舍入。这里证明的是这两个保存点、这一批数据的单步精度损失，**不是“全程99%训练无效”，也尚未证明它解释全部成功率下降**。CPU探针没有完整复现GPU增广/FSDP路径。

最小候选修复：冻结的π0.5继续BF16，只让约727万参数的小SAC网络及优化器保留FP32；概率、损失和温度计算一并核对。新增显存预计为几十MiB量级，实际FSDP分包/特征转换需一次短测。不能把整个π0.5粗暴转FP32，也不应靠猛加学习率跨过量化刻度。

证据：[CPU单步对照](evidence/plateau-20261105/optimizer-ab.json)、[复现脚本](evidence/plateau-20261105/dsrl_optimizer_ab1105.py)。原版JAX小网络默认FP32，BF16并非论文的算法要求；来源见[23](23_DSRL_EXTERNAL_EVIDENCE_20261105.md)。

## 4. 独立噪声确实改变了难度

原π0实验把32个数重复到50个位置，小策略只需决定32个数。我们为保住π0.5的基础表现，改为独立1600个数；实际actor输出、Q输入、回放存储都已核实为1600维，没有只保存前32维。

控制自由度扩大50倍，网络宽度仍128、三层；Q还要从几千到一万余条真实动作块记录中学习。原论文明确说明完整1600维的优化困难；官方仓库π0.5复现讨论也报告过“重复噪声失败、独立噪声可执行，但完整空间难训练”。这支持“需要更好的优化/更多覆盖”的假设，不能据此断言加到某个轮数就会好。[论文C.5](https://arxiv.org/html/2506.15799v2#A3.SS5)、[复现讨论9](https://github.com/nakamotoo/dsrl_pi0/issues/9)

保留独立噪声目前有我们自己的起点成功率依据；重复噪声曾接近零，不能为了降维直接换回。

## 5. 另外两处应排在精度后面核对

**探索范围变窄。** 预热使用完整标准高斯噪声；学习阶段使用`tanh`限制到±1。回放中噪声总体标准差由约1降至0.55–0.65；固定观察下，网络的加`tanh`前标准差均值约0.23–0.30。这不等于完全没有探索，但学生并非仍在原来的噪声分布中选择。官方π0实现按环境使用不同幅度，Aloha脚本是±2；幅度值得单独比较，不能机械照抄。

**Q偏爱新噪声，实际成功率没有同步提高。** 最近日志Q通常给真实回放噪声约−1.2到−1.4，给当前策略新噪声约−0.3到−0.5。CPU保存点探针也看到同方向。因为越接近0越好，小策略看起来在迎合Q的高分；但尚未收集这些反事实新动作的真实后续结局，不能仅凭分数差断言全是高估。

这里的DSRL奖励为每块未成功−1、成功终止0，超时保留bootstrap；这与先前FQL的0/1回报不同，不能套“Q应该不超过1”的诊断。当前critic loss也没有稳定下降，后段常高于刚开始更新阶段；持续变化的数据分布和数值问题都可能影响它。

## 6. 与原实现对齐及尚有区别的地方

| 项目 | 我们实际值/行为 | 本轮判断 |
|---|---|---|
| 小策略/Q学习率 | 1e−4 / 3e−4 | 与官方π0仿真量级相同 |
| batch、UTD、隐藏层 | 256、20、128×3 | 有官方参考；不能保证1600维同样足够 |
| Q与目标更新 | 10头均值，EMA .005，不往Q答案加熵 | 与官方π0路径一致；不是遗漏双Q最小值就必然写错 |
| N/H/C | N10/H50，RT2 C20、Dojo C50 | 与各自已确认控制协议一致 |
| 任务时限 | RT2 200动作；Dojo700动作 | 不把RT2官方400上限擅自改进当前训练 |
| 视觉输入 | 单主相机64×64＋14维本体状态 | 官方仿真有同类设置；不等于我们的CNN实现完全相同 |
| 编码器 | 双独立CNN，flatten后64维瓶颈 | 与官方空间聚合细节不同；本轮没有证据证明是主因 |
| 数值精度 | 在线小网络/Adam BF16 | 与官方FP32不同；已有直接舍入证据 |
| actor Adam β2 | .96，Q为.999 | actor沿用本地配置，不是官方默认.999 |
| 初始温度/熵目标 | .02 / −800 | 高维适配选择；当前熵约−800，目标可达，温度约1e−4 |
| 评估 | 随机噪声策略，非全部零噪声/只用均值 | 未发现评估误走确定性零噪声路径 |

模型参数同步、回放奖励/结束标志、1600维噪声存取、状态/图像归一化路径均有实际代码或产物支持；不把尚未做的新端到端行为对照说成已通过。梯度有值、未见NaN，也不普遍顶满裁剪阈值，暂不支持“更新整体太大”是首要结论。

## 7. +U为什么暂时也救不了

+U读取同观察、同噪声的N5/N10动作差异，在执行段真实14维聚合；τ=2.5，给小策略的`α logπ − Q`整体乘权重，不改变奖励或Q监督。当前权重大致0.84–1.28、均值1，主要是温和分配学习力度。它不能自动让Q学准，也不能解决BF16吞掉更新；现阶段不宜以此否定或肯定U本身。

## 8. 建议收敛顺序

1. **先单独修数值精度**：FP32小SAC网络/Adam，保留当前基础模型、独立噪声、学习率、UTD及采样协议；短测真正有参数变化和续训后再比较成功率。
2. **再看噪声范围与Q可靠性**：小规模比较幅度，记录当前策略真实轨迹的Q与后续回报；每次只改一个主要因素。正式判定提升时，RT2不要只看12局峰值。
3. **最后才考虑更大网络/更多数据/Noise Aliasing**。延长采样与提高UTD是两件事；已存在更新精度问题时，不优先把20改40。

本轮只分析。4–7正式任务及400轮接续/RLT调度保持，所有新诊断只使用CPU；未把修复悄悄混进现有曲线。
