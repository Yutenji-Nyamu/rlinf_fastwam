# 本轮目标与停止深挖的边界

目标只有一项：在扔瓶子任务上，用官方Dojo π0.5跑通Clean GRPO，并得到同一评估协议下的成功率曲线。6/7接Dojo，4/5现有实验保持；Dojo结束或无法继续时接原RLT。2026-11-03当前仍在真实采样/更新短测，未获得正式RL结果。

## 保留什么，放弃修什么

- 保留已通过的同权重转换、原生相机/动作/奖励、模型合批、G8同初态和真实终止掩码。算法仍200轮，每轮256局，N10/H50/C50。
- 不再增加渲染、驱动、Isaac内核优化。H100缺RT Core，NVIDIA未将其列为受支持的Isaac Sim渲染卡；现有兼容层可运行不等于所有场景稳定。[官方要求](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)
- Dojo官方也区分坏物理状态与正常失败，并使用跳过布局、补采、保存进度、最多3次进程重启。[官方恢复实现](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/main/src/eval_client/main.py)

## 最小外层规则

| 情况 | 处理 |
|---|---|
| 机器人正常执行但未完成任务 | 计0分，保留为GRPO训练数据；不按成绩筛布局 |
| 初始化物理错误、同G8初态不一致 | 留布局/误差记录，整组替换；当前最多8次；仍失败回RLT |
| 运行中物理/设备错误、原生RPC超时 | 本次未完整保存的轮次作废；原owner精确清场并接RLT，准备好后重启Dojo，从最近完整点重采 |
| 同类正式仿真故障反复出现 | 外层总计最多3次重启；达到上限保留RLT，不无限调试/空等 |
| 用户主动停止、模型/优化器/磁盘/未知代码错误 | 不伪装为物理异常反复重跑；精确退出接RLT，报告具体故障 |

正式训练每轮完整保存一次，仅在新点完整落盘后滚动淘汰旧大文件；日志曲线全留。已评估的RL提升候选按保护权重规则另存。重启沿用同一个run和200轮总预算，训练布局重新抽样，评估池不主动改动；具体物理缺测另记。

实现复用`tools/dojo_chunk_eval/recover_queue.py`的有界外层恢复思路，以及现有`priority_pair_handoff.py`和Clean私有Ray清场。新增`tools/dojo_grpo/recover_queue.py`只处理进程和配置，不改仿真控制器；必须先通过真实更新/保存/1→2恢复，才允许自动恢复正式训练。
