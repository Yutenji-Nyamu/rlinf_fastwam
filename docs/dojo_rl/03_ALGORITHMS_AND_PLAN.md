# 算法选择与第一轮方案

## 先回答如何选

| 路线 | 通俗机制 | 现有依据与选择 |
|---|---|---|
| **Clean GRPO，先接** | 同一开局尝试多次，增加成功做法的出现概率 | 我们已有π0.5完整训练/续训链，无需另训Q或价值网络；最方便隔离Dojo适配问题 |
| **PPO，第二候选** | 边尝试边学“当前局面还有多大成功希望”，据此判断动作是否比预期好 | RLinf有π0.5正式实现；官方LIBERO表里PPO优于GRPO，但不能直接外推Dojo |
| EXPO | 学小修正器调整原策略，并用Q给修正打分；策略也继续学习 | 我们Robotwin turn_switch Clean B64曾40%起步、末次85%、峰95%，但每评20局且后五次均值69%，明显波动；多了Q、回放、修正器，不是首个环境接入的最小方案 |
| DSRL / RLT | 通过可训练噪声或辅助策略改善已有策略 | 有候补和运行经验，但Dojo需要不同模型/动作与数据接入；“候补正常”不等于已在Dojo证明收益 |
| 当前FQL系列 | 用已有转移训练Q，再让一步学生模仿老师并追求高Q | 我们已见Q高估和成功率先跌等问题；不把它作为新环境首个在线RL基线 |

“最快复用”与“最后谁更强”是两件事：建议先Clean GRPO建立可信基线，PPO作为最优先的下一算法。官方π0.5在LIBERO表中77.1%起步，GRPO91.5%、PPO97.9%；这些是作者在其他benchmark的结果。[RLinf](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/pi0.html)

我们自己的GRPO也并非从未提升：药瓶Clean CP140配对128评估72/128=56.25%，Uτ1历史收束前五评均35.625%、末五评均60%。这些属于RoboTwin，协议和训练不同，只支持“该链跑过有效学习”，不用于给Dojo预报提升幅度。EXPO收束证据见仓库既有 `docs/experiments/pi05-followups-20261019/expo-closeout.json`。

## 一轮Clean GRPO实际做什么

1. 抽一些训练布局，每个布局复制8份，机器人和物体初态相同。
2. π0.5用不同随机噪声生成动作，完成尝试；只把真实执行、有效结束的轨迹交给学习。
3. 比较这8次的成败：成功者高于组平均，失败者低于平均；全成/全败组没有这种成败区分信息。
4. 用既有Flow-SDE训练链计算动作概率并小幅更新动作专家，再采下一轮。视觉语言部分先冻结。

Flow-SDE是让原来的流生成过程拥有可记录概率的随机采样方式；原生JAX推理返回动作本身不够直接做PPO/GRPO。应复用πRL/RLinf和我们已验收的实现，不自行给最终动作随意加噪后套概率公式。[πRL](https://arxiv.org/abs/2510.25889)

## 建议的起始设置（均未启动）

| 项 | 起点 | 依据/待确认 |
|---|---|---|
| 模型 | 官方Dojo π0.5 checkpoint59999，优先seed1候选 | 历史扔瓶子52%、叠碗48%；复验后固定权重，不按每轮成绩换底座 |
| 任务 | 先扔瓶子，备选叠碗 | 700/800原生上限；不套RoboTwin的200或400动作 |
| 动作 | N10、H50/C50 | 原Dojo基线；以后C10是另一个变量，首轮不混入 |
| 可训练部分 | 动作专家，冻结VLM | 当前Clean GRPO的 `train_expert_only=true` |
| 学习率/裁剪 | `5e-6`，梯度裁剪1.0 | 当前已跑通Clean实配；不是Dojo官方调参结论 |
| 组大小/采样 | G8；每轮候选256局，首试每卡32、双卡64×4批 | 本轮重新按总局数与组整除收敛；原生25环境是容量参考，32尚未验收 |
| 更新batch | global512、micro32，原数据学习2遍 | 沿用现行Clean；Dojo轨迹更长，每轮更新次数随块数增加，详见06 |
| 奖励 | 完整成功一次1，失败0；部分Score另记 | 环境直接判定，减少奖励设计变量 |
| 普通评估 | 关闭录像、U、DV与逐动作采集；保留成绩/用时/错误 | 已跑通的轻量评估经验；debug只留少数可定位轨迹 |
| 保存 | 最新完整续训点滚动，日志曲线全部保留；RL评估峰值/指定候选另存保护目录并登记 | 沿用现有存储与保护规则；不擅删旧保护点 |

本轮用256计划局收敛后，替换早先24/卡候选：先测32/卡，若显存或吞吐不合适，补一个16/卡调整点，串行4批改8批，仍256局。判断依据是有效回合/小时、reset耗时和完整采样+更新峰值，不以显存占满为目标。不能直接引用JAX纯推理25环境为PyTorch训练显存保证。完整参数来源见[06](06_PARAMETER_PROVENANCE.md)。

## 实施顺序

1. 无卡准备：按02修接口、固定权重转换规则、训练/验证布局划分、配置与停止条件。
2. 短验收：同观察同噪声原生/转换动作对照；一个完整采样→更新→保存→续训周期。需要验证组内初态、成功/超时、有效步mask；不用从零重写已跑通仿真流程。
3. 基线：选定任务约128局，固定验证布局，报告真实有效数；独立布局少时重复噪声次数另列。
4. 当前候选总预算200轮，中评0/2/5、之后每5轮；前20轮用于观察上升和组内信号，不将其设成已经批准的20轮硬停止。实际启动仍待选卡与实现授权；中评32局、末评128局及布局划分见06/07。

完整RL墙钟时间目前不报确定ETA：Dojo的reset和700–800步上限与RoboTwin200步不同，而且训练后端尚未测通。首段报告采样、重置、更新、评估四项用时，再估剩余。过去叠碗25局采集批次约37–48分钟且带录像/额外U，只是历史量级，不能直接当无录像RL速度。
