## 代码切口

- `rlinf/envs/robodojo/robodojo_env.py`：RLinf Gym接口，只负责分组、RPC和张量。
- `tools/dojo_grpo/native_entry.py`：直接复用原Dojo main创建环境，原生并行执行；不另写物理控制器。
- `protocol.py`：固定布局、分组、提前成功一次奖励及实际执行位置。
- `convert_jax.py` + `convert_pytorch_layout.py`：复用仓库转换器；适配NNX value容器与当前Transformers的共享embedding别名。
- `pair_owner.py`：复用已有精确RLT交接和Clean Ray namespace清场。

原生模型输出经`AbsoluteActions`恢复关节绝对目标；用Dojo自己的`pack_robot_state`/`unpack_robot_state`映射左右臂和夹爪，不混用RoboTwin排列。

## 启动前列明的验收

1. CPU：分组完整、布局切分无重复、奖励一次发放/终止后掩码；转换全部参数键/形状。
2. GPU：真实观察和同噪声下JAX/PyTorch动作对齐、单条与B32输出对齐、实际计算/渲染绑定；少量图形残余另记。
3. 原生两路16环境全组同初态、32回合一波完整700步上限、Clean更新/保存/恢复。Smoke全局batch64使448个动作块可整除；正式全局512不变。
4. 通过后同源正式200轮；普通失败、设备错误或停滞进入有界清场并恢复RLT，不无限持卡重试。

状态以执行回执为准：本文件为启动前方案，不代表上述GPU验收已通过。

## 当前验收与故障收敛

- CPU转换：813个参数键及形状匹配，无缺失。GPU同观察/同噪声的JAX与PyTorch实际动作RMSE 0.002103、最大绝对差0.010087，状态和tokenized prompt完全一致。
- CPU六项协议检查通过，另用现行Clean的真实batch预处理/GRPO汇总验证：第17动作成功的1分保留，后续动作块被屏蔽，没有重复记分。
- 7卡两次独立Isaac启动出现内核Xid109，CUDA/RLT仍能运行。暂用6卡承载两路仿真；未reset GPU，未暂停4/5或其他用户。
- 私有Kit缓存需要URDF扩展2.4.31，显式复用已下载扩展，不修改共享安装；材质S3路径直连测试成功，17890失败，本次仿真使用直连。
- 原生全局物体计数器导致各环境实例名不同。组内检查改按同型号第几件物体对应，继续核对真实局部位置（5mm）和朝向（2度）；不同资产/数量仍报错。
- 实际32环境同初态验收通过：物体最大位置差0.0067mm、朝向差0.0077度；机器人状态差约6.2e-16。三相机真实观察已保存并目视检查。
- B32模型推理0.78秒，模型张量峰值11.52GiB；B1/B32实际动作RMSE 0.000638。此数值不包含仿真和更新，不作为整轮速度。
- 验证池首批有4个布局物理初始化不稳定。复用旧采集的物理报错跳过语义：留异常清单、换未用的候选布局，训练时整G8组替换；最多3次reset，仍失败则返回RLT。只看物理有效性，不看策略成败。每批保存请求/实际布局及替换记录，接口同步真实reset IDs。它是自定义holdout，不冒称原55局完整官方评估。
- 实际主计算/渲染在6卡；原生进程各在4卡产生约7MiB纯G上下文，已按工作区残余规则记录。没有把它报成完全无占用，不为此中断健康4/5。
- 手动停止恰逢失败清场，第二个SIGTERM曾打断释放。已改为清场期间忽略重复停止，精确移除本轮残余，RLT恢复后才重新交接。
- 这些都是接入验收问题，尚无有效Dojo训练成绩；未把启动通过当成RL跑通。
- R9发现适配遗漏了原生`run_eval()`开头的`run_reward()/get_score()`注册，造成一步误报成功；该批成绩作废，没有执行参数更新。已补回原生注册，并在每次reset后检查成功条件非空。
- R10补齐物理初始化状态检查：原生`check_layout_stability()`直接修改`success/end_flag`，不保证填入`unstable_envs`。重置后联合检查这几路状态及`layout_valid`，新增回归检查覆盖该原生分支。R10未进入参数更新。
- 卡位优先：材料准备保持RLT；两路仿真在6卡初始化时，7卡继续RLT，仅在模型训练即将启动时交接7卡；失败清场自动释放给原RLT。没有用空转程序占卡。
- 首个50动作块实测：原生控制/物理/奖励约40秒、额外逐动作取图约136秒，约77%是模型没有消费的中间图像。新增chunk边界取图：50个动作的原生执行与奖励调用不变，每块结束才获取下一次模型输入；原生终止帧捕获保持。先做相同初态/动作的10动作对照，比较机器人状态、三相机画面和成败标志，结果另存。
- 已知7MiB纯图形残余改为启动时按精确PID、类型与显存上限自动核对并记录，避免反复人工等待；新的计算串卡仍直接退出接RLT。正式预算由200轮决定，不额外加未讨论的14天硬截止。
- 取图对照第一轮：10动作由15.75秒降到8.47秒，机器人状态完全一致、成败与奖励一致；头/腕相机平均像素差1.72/3.34（0–255）。最初无依据的3像素门槛拦下了后续，未作为成功率异常处理；改为保留像素差报告，并通过真实π0.5比较同噪声动作变化来判断影响。

代码沿用当前可用的原生Dojo与Clean GRPO环境，不新增通用安装器/Docker支持。训练私有配置和RPC密钥分开保存，公开源码与轻量结果不含密钥。
