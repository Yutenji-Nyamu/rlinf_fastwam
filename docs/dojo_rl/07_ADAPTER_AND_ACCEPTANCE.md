# 增量实现切口与简短验收

2026-11-03规划；未修改运行中的训练，未占新卡。高层目标是用官方Dojo π0.5在单任务上建立可复现的在线Clean GRPO提升曲线；两卡有效并发，保留成功评估/恢复经验，避免迁移时改变算法和任务定义。

## 代码怎么接

```text
RLinf EnvWorker（薄适配）
    ⇄ 每卡一套原生Dojo多环境进程：批量reset/观察/执行
    ⇄ 已转换的同一π0.5：批量Flow-SDE采动作，保存旧概率
    → 256局按G8分组算优势
    → 现行双卡FSDP Clean更新动作专家
    → 权重同步，下一轮
```

环境进程沿用原Isaac虚拟环境和正常的AppLauncher导入顺序；模型/RL使用已跑通PyTorch环境。批量进程通信仅在reset/每个动作块边界传三相机与状态，物理执行仍在原Dojo进程。复用既有共享模型服务的进程边界经验，不复制每环境一个Isaac，更不把旧JAX权重服务当可微训练器。

## 模型与仿真共同决定的接口

“相机/归一化都是仿真决定”并不完整：**仿真决定提供什么，checkpoint训练配置决定模型期待什么**。本次官方模型使用ALOHA排列、12维delta关节和2维absolute夹爪；环境要原生排列及真实关节目标。转换器按同一个观察保存的state还原动作，概率计算仍留在原模型空间。不能先在wrapper排一遍、model transforms又排一遍。

先做同观察/同初始噪声N10 ODE的JAX/PyTorch对照，包括最终实际14维动作。数值允许浮点实现差异，需看关节/夹爪误差和实际执行是否一致，不要求不同框架bitwise一致。通过后再启用原Clean Flow-SDE，分别记录采样成功与普通N10评估成功。

## 初态、布局和随机数

现场资产中，两个候选任务在布局组0/1/2各有55份标准布局文件；这不等于每份都稳定可用，也不等于历史评估实际跑了55局。历史扔瓶子50局、叠碗25局应保留原分母。

最简候选划分是布局组0/2用于训练、组1固定验证；模型权重始终seed1。启动前按场景内容排除跨池重复，只做原生物理有效性检查，不按策略成败筛布局。报告“自定义训练/holdout划分”，不宣称完整官方benchmark。若现有模板不能形成独立池，再用原生布局生成器补训练布局，不能仅将`random=True`当实现完成，更不能顺带加入_random任务的干扰物/视觉随机化。

每轮32组，每组8个slot共用layout/场景seed，策略噪声不同。跨环境的位置比较要扣除Isaac环境平移原点。原生reset把seed送到scene/robot/camera manager，仍需检查slot编号是否额外进入随机路径，不能只看传入参数相同。一组有物理坏例时整组按同一候选布局重置，有限重试；不只换坏slot造成组内不同题。

## 成败与末块：保留算法粒度

原生EvalEnv把 `success` 初始化为True，它在运行中还承担有效状态含义，**不能直接把这个布尔值当任务已完成**。奖励依据原生reward_manager/结束判据：新结束且成功才记首次1；超时/正常失败0；物理报错缺测。保留原生final_check的调用条件，不照抄另一个桥每动作强制final_check=True的语义。

例：一块生成50动作，第17个动作成功。保存真实执行数17和终态；奖励放实际终止位置，不能落在随后被mask丢弃的padding里。后33个未执行位置用于说明动作截断，不伪装执行记录。下一块不再参与该回合训练。

**当前Clean以整块为策略动作、以chunk-level概率更新。** 生成完整H50后环境只消费前缀，不自动意味着整块概率公式错误；本次先保持这一算法定义。执行位置mask必须传到记录/成败汇总，已结束后的块在loss中屏蔽。如果要改为“只计算执行前缀的概率”，属于额外算法变化，不能借环境迁移悄悄改动。旧Control并不读取新PR的`infos.valid_action_mask`，因此不能只增加这个字段就宣称训练已经对齐；必须用确定的小例子走完EnvWorker→轨迹→actor汇总，验证1分不丢、后续块不学。

## 短验收就够，检查有具体目的

1. **无卡**：维度/顺序互逆；成功17步、跑满时限、坏组缺测三种小例子；256/G8/批次整除和保存/续训配置。训练文件与既有版本隔离。
2. **同权重推理**：固定少量原生观测/噪声核N10转换，并直接验证候选32环境/卡的完整动作循环；必要时只补一个16环境调整点。
3. **完整学习周期**：256计划局→优势→2遍更新→完整保存→续训；确认VLM未更新、动作专家有有限梯度、组内布局一致、成功奖励只有一次、三项用时可估。
4. **基线和正式方案**：在固定holdout约128局记录起点；正式评估/总预算见06。异常组有记录、有限重试，持续故障结束本实验并接原有队列；保留每卡RLT及无保存兜底。

最值得看的是有效局/小时、每组成功数分布、reset/仿真/推理/更新用时、评估成功率和KL/clip比例。没有依据添加每步重复磁盘校验、全轨迹重读或额外录像。启动前再读取卡位，准备完整后才交接，用户本轮尚未指定实际使用哪对卡。
