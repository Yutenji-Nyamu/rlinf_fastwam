## 为什么先修精度

旧实现的可训练小网络和 Adam 历史量使用 BF16，较小更新可能在存回参数时消失。现在约 **7,269,578 个可训练参数**、Adam 动量、温度和 TD 计算用 FP32；冻结 π0.5 保持原有精度配置，主体 BF16，既有 FP32 层不强制改动。

实际模型验收包括三次 GPU 前后向、梯度裁剪、Adam 更新和保存恢复。约 672 万个参数值发生改变；所有小网络状态及 Adam 动量确认为 FP32。四组均完成真实环境 smoke1→完整保存→smoke_resume2。见各槽位的 `fp32-model-contract.json` 和现场回执中的 `complete_checkpoints`；短测使用较短 horizon、UTD2，不冒充正式 UTD20 训练。

需要同步处理 FSDP：小网络和冻结骨干成为独立包装单元；通过 `forward` 调用噪声策略，确保 FSDP 钩子执行。首次测试暴露了冻结根参数在 full state_dict 保存时缺失，已通过单独包装冻结骨干修复，并重新完成完整保存/恢复。

学习后噪声为 `2*tanh(z)`，范围 ±2；高斯预热不变。动作生成器输入范围改变，机器人关节动作不直接乘2。同步修正确定性分支、缩放的 log-prob Jacobian 和分布变换顺序。±2 属于本轮方法设置调整，不能当作透明加速的收益；对照加速时所有候选都使用同一 FP32/±2 基线。[官方 Aloha 的幅度配置](https://github.com/nakamotoo/dsrl_pi0/blob/7f48937d4553e95244cd81c79236a3256df80597/examples/scripts/run_aloha.sh)

## 同批测试了什么

两套 benchmark 测同一批方案，允许组合测试。借鉴 LeanRL 等项目减少 Python/算子提交开销的思路，底层直接使用 PyTorch；没有把外部训练循环的 loss、Q 聚合或 replay 语义搬进来。

| 候选组合 | RT2 ms/update | Dojo ms/update |
|---|---:|---:|
| FP32/±2 基线 | 104.09 | 105.86 |
| 只集中回传指标 | 107.03 | 91.68 |
| 上项 + fused Adam | 116.72 | 84.04 |
| 上项 + Q 批量计算 | 108.05 | 78.35 |
| 上项 + foreach EMA | 102.94 | **76.96** |
| 指标/fused/Q批量 + 默认编译 | 108.99 | 95.05 |
| 指标/fused/Q批量 + reduce-overhead 编译 | **91.04** | 94.88 |
| 指标/fused/Q批量 + GPU回放镜像原型 | 90.22 | 107.72 |
| CNN channels_last，及其组合 | GPU 输出检查失败，跳过 | GPU 输出检查失败，跳过 |
| 基线再跑一次 | 126.56 | 129.50 |

RT2 选择组合相对较快的基线 **1.143×**（时间约少12.5%）；Dojo **1.376×**（时间约少27.3%）。RT2 的 GPU 回放镜像只比选中组合快约0.9%，没有足够额外收益支持增加生产回放管理逻辑；Dojo 中更慢，因此未接入。

通俗地说：集中记账，避免 GPU 每算一个指标就等 CPU；把多个 Adam/目标网络更新合并提交；10 个 Q 仍保留10套参数，但一起做矩阵计算；编译器再合并 Q 的小操作。没有减少训练更新次数或模型去噪步数。[PyTorch Adam](https://docs.pytorch.org/docs/2.11/generated/torch.optim.Adam.html)、[FSDP](https://docs.pytorch.org/docs/2.11/fsdp.html)

**这些是完整 SAC 更新阶段的短测，不是整轮或 π0.5 推理倍率。** 同一次实验末尾的基线慢约22%，说明共享服务器负载有明显波动。选择使用两次基线中较快者，仍不足以证明长期稳定提升。冷启动/编译时间单列在原始 JSON；整轮还包含环境、重置、评估和保存，正式收益需从相同预算日志继续观察。

## 数值与数据流验收

- 使用生产 `update_one_epoch`，B256；每组5次预热、5个窗口×20次计时更新。
- RT2 13,105 条、Dojo 5,604 条真实历史回放；每组恢复同一 FP32 小网络、Adam、LR、目标 Q/shadow、alpha、更新计数以及 PyTorch/回放/critic/numpy/Python RNG。历史回放只用于丢弃式速度对照，正式运行没有继承它。
- 独立 Q 检查覆盖逐头输出、输入梯度、参数梯度和保存键。所有被采用组合的随机序列及回放抽样状态相同；没有改用 min-Q。
- 连续105次更新后，参数偏差门槛预设为 `max(1e-3, 2×基线重复偏差)`；固定观测及同噪声的策略输出 RMSE <0.002、最大差 <0.02。RT2 选中组合 RMSE 0.000686、最大差0.003308；Dojo 0.000230、0.001119。通过表示在该短测容差内，不是逐位一致或长期轨迹相同。
- CNN channels_last 在 GPU 输出检查中失败，未放宽该检查阈值、未用于正式运行。可选加速失败被单独记录，不再使已经验收的 DSRL 修复一起失败。
- 正式配置保留8局/轮、global=micro256、UTD20、独立50×32噪声、10Q均值、N10；RT2 C20/max200/warmup2000，Dojo C50/max700/warmup500。+U 保留同观测同噪声 N5、τ2.5、只加权 actor 的整项 αlogπ−Q。

## 没有直接搬进来的组件

RoboScope 的环境并行和模型副本数，与我们已有 batch 推理不重复计益。RT2 已经动作块末取观测；Dojo 已有 tiled camera 和减少中间 CPU 回读。此前大幅跳过 Dojo 渲染没通过动作对照，这次不再启用。

首批已覆盖指标、优化器、Q计算、目标更新、编译/图模式、回放设备驻留和图像布局。场景常驻/reset、仿真与推理交叠、FlashRT/TensorRT/FP8 尚未实施；它们会触及环境生命周期、时序或模型精度，需要独立验收，不能按外部评测倍数直接进入正式训练。先保留本次局部有效组合，后续按整轮日志决定下一批，不把现有训练长期留在测试队列。
