# 09-07切换：归一化与标尺为什么这样选

## 1. 执行范围

本轮按最新授权执行BC8条/U2与GRPO chunk-ST/positive-only。不是将仍在讨论的BC共同中心化一起上线。

两BC原SFT、空池重新开始，只改32→8条与U10→2；global1024/micro32不变，因此每轮成功池有数据时有放回抽2048个chunk做两次Adam。沿用历史5轮标尺后，覆盖的训练尝试预算从约160缩到40；这是窗口不变的算术后果，不是偷偷另调窗口。每轮8不是8条成功，而是8次尝试；无成功池时仍沿用原空池跳过规则。

## 2. 为什么建议跨新成功chunk共同中心

方法意图包括“整段重要，就整段多学”。逐chunk均重1会把整段共同偏高的信号抵消。将中心取在本轮新成功池，允许同一轮chunk间强弱不同，同时总体均重1；入池一次计算、旧权重保持固定，不引入额外模型或replay重标定。

这是**有常见组成部件的本项目设计**，不是已找到某篇论文原封不动使用“本轮全部新成功chunk减共同z均值”。

- [AttenA+ §3.3.2](https://arxiv.org/html/2605.13548v1#S3.SS3.SSS2)明确使用权重限幅，并允许归一到均值约1以控制整体损失尺度。它支持保持平均监督力度的动机，不规定本项目的在线分组域。
- [SARM/RA-BC §3.2](https://arxiv.org/html/2509.25358v1#S3.SS2)给不同训练item赋不同权重，并用总权重归一加权损失，支持跨样本差异。它是按chunk平均误差后加item权重；我们保留action-level，不复制其粒度/阈值。

不应声称均重1就保证最终梯度范数或有效学习率完全不变；权重与误差/梯度的相关性仍会改变总梯度。共同中心也不能解决DVAC是否真正衡量重要性的问题。当前用户只同意其大方向并询问依据，本轮BC仍采用原逐chunk转换。

## 3. log、过去5轮、±2：依据与边界

| 选择 | 原设计理由 | 依据强弱 |
|---|---|---|
| log(V+1e-12) | 正方差信号跨度大时压缩量级，避免极端值支配标尺；epsilon防log0 | 常见数值处理，继承项目已有GRPO；不是原DVAC论文规定，也未证明此任务最优 |
| 历史均值/std | 把量级转成相对高低，随策略变化更新标尺 | [RA-BC](https://arxiv.org/html/2509.25358v1#S3.SS2)明确采用在线均值/std；[EAPO §5](https://arxiv.org/html/2604.11056v1#S5)也将信号标准化后限幅 |
| 仅前最多5轮 | 使用已完成轮次，当前轮先定权再入统计，避免当前批改变自身参照；短窗口适应策略漂移 | 5是工程选择，不是文献给出的本任务最优窗口 |
| 新成功＋失败query进标尺 | 标尺描述当前采样策略遇到的分歧，不只描述被筛选的成功子集；失败不进BC监督池 | 本项目选择；失败V分布不同也可能改变成功权重，必须视为方法约定，不说成唯一合理做法 |
| 旧replay不重复进统计 | 防止抽样次数改变“新采集信号分布”的计数 | 与使用采集统计的定义一致，不是增加学习数据 |
| z限[-2,2] | 限制异常点贡献；结合映射确保非负且在约定范围内 | RA-BC也使用μ±2σ区间的线性限幅，是具体先例；但它信号是进度，不是logV。阈值2仍可调，不能解释成已验证95%覆盖 |

总之：**标准化＋有界权重很常规；log、窗口5、统计哪些样本、在哪一层均重1，是需要明确记录的设计选择。** 它们不是BC必需模块，也不能仅凭引用称为已验证最佳。

## 4. GRPO本次真正的改法

`scope=all`保留原两侧重加权；新正式配置`scope=positive`：原始优势A>0时用DVAC，否则w=1。负反馈没有删掉。当前二值奖励的混合GRPO组中，正优势对应成功；全同结果组仍走原过滤逻辑。

[STARE-O1](https://arxiv.org/html/2606.19236v1#A7.SS4)提供正侧子集重加权先例，但不保证我们的正侧DVAC比两侧好。[EAPO](https://arxiv.org/html/2604.11056v1#S5)反而增强正负两侧高熵位置，说明这是方法选择，不是行业统一规则。

前向使用旧`logprob_st`，原logprob值不变→按baseline整chunk聚合→原ratio/clip；反向逐动作乘有效w。不是把旧action-adv做等价重写，不再改变baseline裁剪粒度。生产代码仅新增scope函数25行、actor16行，加方法YAML、测试和说明。20项CPU回归＋旧真实[4,128,50]权重/[4,128,1]优势检查已通过；未做GPU模型smoke、长程或完整恢复测试。
