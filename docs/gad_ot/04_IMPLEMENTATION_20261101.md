# Direct + GAD-OT实际实现（2026-11-01）

## 先用普通话理解

一个场景，老师提出4套完整动作，学生也提出4套。以前按编号配：学生1学老师1。现在先算16个距离，再整体安排4组配对，让总距离最小；每套老师动作都用一次。不是把老师动作求平均，也不是每个动作时刻随便换老师。

例子：老师给“左绕、右绕”，学生已经会“右绕、左绕”。原编号配对会把两个都判成大错；调换老师编号后，可以认可学生已经覆盖这两种行为。只有在两种行为确实有效时，这个例子才说明收益；距离下降不等于机器人成功率上升。

GAD继续决定“哪些动作值得多学”，OT决定“同一场景下向哪套老师动作学”。本轮只实现Direct上的组合，独立配置开关，不修改正在跑的四条GAD方法。

| 训练 | 每卡224，全局448；400预算轮=4400次更新；clip1 | 既有Direct＋GAD测出的并行和训练预算 |

| 评估 | 27次×128回合，双卡各32环境×2批，原held-out seeds；不录像、不采信号 | 原single_formal_queue，评估协议不变 |
| 供数/保存 | 8线程解码、一步预取；Data，每实验最新完整续训点；日志曲线全留 | 既有供数实测及用户最新存储规则 |

**对照边界：** 旧GAD用K4旁算信号，主损失另抽独立噪声。本版为了复用候选，只在K4里均匀选一行计算主损失。因此与旧GAD相比，除配对外还有主损失噪声与信号集合相关性变化。未来严格拆分OT收益，应加一个同样K4抽行、仍按原编号配对的对照；本轮不另增队列。候选和匹配停止梯度，抽行梯度只对应固定有限集合目标，不宣称它是总体Wasserstein距离的无偏梯度。

## 与OptiFlow的准确关系

[OptiFlow固定版本源码](https://github.com/Yonsei-DILLab/OptiFlow/blob/d54ad7364646bed9405bf0b7fe313eea9587f3bf/optiflow/agent.py)先让Q为老师候选分配份额，再用动作距离求Sinkhorn软分配；最后每个学生取本行权重最大的老师，用该配对质量加权模仿。多个学生可以选同一个老师，不能把其代码说成严格一对一。

本版保留“同条件候选＋动作距离整体配对”思想，不引入Q，四个老师各占1/4，直接求精确排列。K4、均匀份额、硬排列都属于明确的适配，不是原论文16/64候选及ε0.05的复现。

## 为什么本轮先落Direct

| 方法 | 当前loss两边是什么 | OT如何接 |
|---|---|---|
| Direct | 学生完整动作 vs 老师完整动作 | 可直接换目标配对；本轮已实现 |
| CP v2 | 一项预测示范加噪后的速度；另一项是同一噪声路径的相邻时刻一致性 | FM项的答案是专家示范，不是四个可互换老师端点。若换它，就改变专家监督；若增加端点OT，还需新系数 |
| DMD new | 在同一学生含噪位置，比较老师和辅助网络给出的修改方向 | 当前没有“学生i模仿老师j”端点项可直接替换；可以另加OT引导，但不是换一张配对表 |
| MFD | 老师和辅助从同一位置各积分一小段，比较平均修改方向 | 同样需要另设计端点正则或运输方向；不能跨配含噪位置破坏原方向定义 |

所以“CP只改模仿项”需要先区分模仿谁。我们当前CP的FM监督来自专家动作，不能当成Direct的老师答案。DMD/MFD不是不能用OT，而是需要一个新目标和强度控制。

## sDMD与多种正确解

[sDMD](https://arxiv.org/html/2610.39889v1)处理DMD的局部指导在远离教师分布时不足的问题。它增加“学生到老师”的运输拉力，再减去“学生到学生”的偏置项；用DMD2判别器控制何时介入，减少对已在合理区域的样本的干扰。其目标是带去偏项的Sinkhorn divergence，不等于本版硬配对MSE。当前DMD new没有该判别器，本轮也不添加。[项目](https://sinkhorn-dmd.github.io/)在本次查询时Code Coming Soon，不能声称已审其官方实现。

[Diffusion Policy官方介绍](https://diffusion-policy.cs.columbia.edu/)明确以表达多模态机器人行为为优势；[COT Policy](https://proceedings.mlr.press/v305/sochopoulos25a.html)也研究多模态条件动作分布。可绕左也可绕右、可用不同抓法，都是“分散但可能正确”的例子。这个观点很常见；但不能由此认定我们观察到的所有教师分散都是好行为。K4标准差只能测输出有多不同，不能单独区分合理多解与错误不稳定。

## 源码切口与必要验证

- `gad.observe(..., retain_candidates=True)`可选保留K4完整噪声及师生14维端点；默认行为保持，已有方法不变。
- 新`rlinf/algorithms/pi05_distillation/ot.py`负责成本、精确匹配、随机选行、端点损失；严格仅允许endpoint＋GAD＋14维配置。
- `train.py`仅在显式`gad_ot`合同时接新损失；原CP/DMD/MFD分支保持。
- `test_gad_ot.py`检查整体匹配、动作权重、观察隔离、梯度尺度、14维mask、teacher/权重停止梯度及RNG兼容；与原GAD检查共13项。
- `gad_ot_smoke.py`调用原GAD的12→14续训、N1导出与B32实际模型推理检查；临时大权重按原smoke规则删除。此项不含闭环仿真成功率，不当作效果结论。
- 正式用原`single_formal_queue.py`，失败只清自身进程并释放给既有RLT；不新增全局GPU管理器。

GPU短测资源为当时最高编号可达空卡1机2/3。2/3机从本机与1机两条入口均在SSH握手前超时，不能推断其GPU状态。正式等当前队列正常完成，接较早结束的队列，具体身份和ETA写入05回执。
