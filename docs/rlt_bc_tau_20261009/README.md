## BC为什么不同、为什么慢

实际配置比较排除方法、运行路径和资源位置后，仅预算从100轮延长为300轮；π0.5起点、任务、N8/U5、B1024/micro32、200动作及固定32评估一致。训练和评估种子SHA256一致。

历史Clean与当前方法源码均有`max_success_chunks=3`，同一行逻辑：**整条成功轨迹超过3个chunk就不进成功池**。这不是新增过滤，也不是把每个chunk裁成3步。

共同R80–100五次固定评估均值：Clean62.50%；U2.5无trick48.75%、Norm2.5无63.12%、U3双60.62%、Norm2双59.38%、U3仅drop58.75%、Norm2仅drop60.62%、U3仅退火57.50%、Norm2仅退火61.88%。多数靠近Clean，不能说全都明显更差；单次32条、单seed不能证明小幅差异显著。

U无trick较差是真实现象。合理但未证实的解释是：分歧/残差范数不一定等于有效控制的重要性，重加权可能压低有用成功样本，并改变后续采集分布。配置审查未找到新增长度过滤或额外预算变化来解释它。
